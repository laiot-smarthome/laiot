# Подготовка сервера по SSH

`tools/install-server.sh` — публикуемый Bash-файл для Ubuntu 24.04
x86_64 с systemd: чистой либо с уже установленной FastPanel.
Запускать только под пользователем root. Доступ в интернет
нужен для установки пакетов и активации FastPanel; белый IP для домашней
установки не требуется. Ubuntu 26 пока не включена: поддержку нужно сверить
с официальным установщиком FastPanel и проверить на отдельном стенде.

Скачайте файл с сайта распространения в `/root/install-server.sh`, затем
запустите в интерактивном SSH-сеансе:

```bash
bash /root/install-server.sh
```

Параметр `--help` показывает справку и не меняет систему. Других параметров
нет: выбор делается вопросами с ответами по умолчанию. Адрес публикации
файла ещё не определён; команда скачивания должна использовать HTTPS.
Не запускайте загруженный файл, не проверив его источник и содержимое.

## Порядок работы

1. Проверка root, Ubuntu и наличия FastPanel. Если панели нет, нужна чистая
   система без работающих веб-серверов и БД. Вторая установка LaIOT с общим
   агентом на том же сервере автоматически не создаётся.
2. Выбор локального или публичного сайта, имени и IPv4 интерфейса сервера.
   Отдельные вопросы — Mosquitto, доступ MQTT из домашней сети,
   Zigbee2MQTT и очистка предустановленных программ. По умолчанию эти
   компоненты и очистка выключены.
3. После подтверждения — необязательная очистка и автоматическая настройка
   swap по RAM. Если FastPanel отсутствует,
   мастер ставит её и показывает новый случайный пароль `fastuser`.
   Пользователь активирует лицензию по email. На готовой панели сохраняются
   прежние данные входа. В обоих случаях нужно наличие PHP 8.3 для сайтов.
   Затем выбирается готовый сайт по ID либо создание нового сайта,
   системный пользователь и отдельный пустой каталог установки.
4. Установка PHP CLI 8.3 и расширений, Redis на loopback, Node.js 24 LTS
   из официального архива с проверкой SHA-256, Composer с проверкой подписи
   его установщика. Node.js и Composer для приложения находятся в `/opt`;
   ссылки в `/usr/local/bin` создаются, только если команда ещё не установлена.
5. Создание нового сайта (или проверка владельца готового сайта) и БД через
   `mogwai`, получение приложения из
   `https://github.com/laiot-smarthome/laiot.git`, ветка `beta`. Для будущего
   перехода поменять `BRANCH=main` в начале скрипта. Повторный запуск
   использует сохранённую ветку, а не обновляет приложение.
6. Установка зависимостей через Composer и сборка `npm ci` / `npm run build`
   под владельцем сайта. Подготовка systemd-агента и шаблонов worker.
7. Настройка корня сайта, обработки адресов и HTTPS в FastPanel по подсказкам.
   Мастер проверяет, что `/install` отвечает HTTP 200. Параметры корня сайта
   не меняются через недокументированные API панели.
8. Показ ссылки, одноразового ключа и параметров подключения. Пользователь
   завершает [веб-установщик](install.md) и возвращается в SSH. Только после
   появления `var/installed.lock` мастер запускает основные фоновые процессы.
   После успешного запуска он повторно выводит полную памятку для сохранения.

Сам SSH-мастер не пишет `.env`, не выполняет миграции и не создаёт
администратора LaIOT: это задача веб-интерфейса. Выберите в нём Redis,
базу `laiot_app`, пользователя `laiot_app`, сервер `127.0.0.1` и показанный
пароль. Снимите флажок создания базы — она уже создана панелью.

## Локальный сайт

Предлагается `laiot.home.arpa`. Установщик показывает запись для DNS роутера
или файла `hosts` каждого клиентского устройства. Сам он не меняет роутер
и не открывает порты наружу. До настройки DNS использует прямую проверку
сайта через выбранный IP и HTTP Host. Локальный сайт открывается по HTTP;
доверенный локальный сертификат можно настроить отдельно в FastPanel.

Для публичного сайта нужен собственный домен, DNS, доступные 80/443 и
сертификат в панели; проверка HTTPS не отключает проверку доверия сертификату.

## Готовая FastPanel и выбор каталога

Мастер получает список через `mogwai sites list`, показывает ID, домен,
владельца и публичный корень. Для готового сайта владелец определяется
автоматически. Для нового можно указать прежнего пользователя FastPanel
или создать нового; флаг `--create-user` передаётся только при отсутствии
системной учётной записи. Пароль пользователя не запрашивается: root
запускает сборку через `runuser` с правами владельца. Группа определяется
через системную учётную запись и подставляется в службы и права новых файлов.

По умолчанию предлагается `/var/www/<пользователь>/data/apps/<домен>`.
Внутри создаются `current` для приложения и `shared` для systemd. Можно
выбрать другой пустой каталог внутри `data`, без пробелов, символических
ссылок и пересечения с публичными корнями любых сайтов. Каталог `data/www`
для исходников не используется. Непустые каталоги не очищаются, владельцы
и права существующих файлов рекурсивно не меняются. Выбранный путь
сохраняется для повторного запуска. В панели пользователь вручную направляет
корень сайта на `<каталог>/current/public`, сохраняя прежние файлы сайта.

Существующие Mosquitto и Zigbee2MQTT не переустанавливаются и не получают
новые пароли: их подключение указывается в веб-интерфейсе. Чужие Node.js
и Composer сохраняются, сборка использует собственные инструменты в `/opt`.

## Ошибка чтения ключа FastPanel в APT

Сообщения `keyring ... not readable by user _apt` и `NO_PUBKEY` после
первой попытки могут означать, что публичный ключ создан с правами `0600`.
Первоначальная версия мастера передавала официальному установщику маску
`077`, рассчитанную на секретные файлы. Теперь только дочерний процесс
установки панели работает с `umask 022`; маска самого мастера остаётся `077`.

При повторном запуске мастер восстанавливает права `0644` только у
`/etc/apt/trusted.gpg.d/RPM-GPG-KEY-fastpanel.asc` и
`/etc/apt/sources.list.d/fastpanel2.list`, если они уже существуют.
Символические ссылки не меняются. Содержимое ключа не заменяется,
проверка подписей APT остаётся включённой. Исправление выполняется до
обновления списка пакетов, в том числе после предыдущего прерывания.

## Автоматический swap

До установки FastPanel мастер читает `MemTotal` и активные swap-области.
Целевой суммарный объём равен RAM, округлённой вверх до целого GiB,
с минимумом 2 GiB и максимумом 8 GiB. Если активного swap уже достаточно,
ничего добавлять не нужно. Область, выключенная вручную или через `noauto`,
в активный объём не входит и автоматически не включается.

При недостатке создаётся только недостающий объём в `/swapfile.laiot`.
Файл принадлежит root, права `0600`; существующие swap-разделы и чужие
файлы не заменяются и не отключаются. Перед выделением блоков проверяется
свободное место: после создания должно остаться минимум 5 GiB для установки.
Недостаток места останавливает мастер с объяснением. Автоматическое
создание поддержано на ext2/ext3/ext4/XFS; для иных файловых систем swap
нужно подготовить их штатными средствами и повторно запустить мастер.

После успешного `swapon` добавляется единственная строка в `/etc/fstab`
с опцией `nofail`. Исходный fstab сохраняется в
`/root/laiot-installer/fstab.before-swap`. Остальные строки не меняются.
План создания хранится в `swap-plan`, поэтому после прерывания мастер
отличает свой файл от чужого и не форматирует уже готовый swap повторно.
Если активация не удалась, запись автозапуска не добавляется.

Проверка выполняется при каждом запуске, включая продолжение старой
установки. Готовый файл можно включить после перезагрузки без пересоздания;
повторные строки в fstab не появляются. Для сравнения объёмов предусмотрен
допуск 1 MiB на заголовок swap. Увеличивать или отключать активный файл
при изменении RAM мастер не пытается: если прежнего размера недостаточно,
показывает ошибку и оставляет ручное изменение администратору. Объём и путь
добавляются в итоговую памятку `access.txt`.

## Необязательные компоненты

Mosquitto требует случайный пароль, анонимный доступ выключен. По умолчанию
он слушает loopback. Для частного IPv4 мастер предлагает дополнительно
слушать именно адрес домашней сети. Файрвол и маршрутизатор автоматически
не перенастраиваются. Параметры брокера затем указываются в модуле MQTT.

Zigbee2MQTT ставится отдельно от SDK-модуля LaIOT, зафиксирована версия
2.14.2. Версия pnpm берётся из её `packageManager`. Настройка координатора
выполняется через собственный мастер Zigbee2MQTT: он слушает `127.0.0.1:8080`,
SSH-мастер показывает команду туннеля с компьютера пользователя. Если
Mosquitto не выбран, запрашивается адрес существующего MQTT-брокера;
его пароль вводится в интерфейсе Zigbee2MQTT. Настройка и проверка Zigbee
не блокируют первую установку LaIOT.

Очистка рассматривает только установленный LibreOffice, Thunderbird,
Rhythmbox, Shotwell, Simple Scan, Transmission GTK, Totem, Cheese,
GNOME Tour и игры Aisleriot/Mahjongg/Mines/Sudoku. Сначала APT вычисляет
список удаления. Если он включает пакет вне этого списка, очистка
отменяется. Перед реальным удалением пользователь видит точные имена
пакетов и подтверждает его отдельно; отказ продолжает установку.
`autoremove`, удаление Snap, рабочего стола, SSH, сети и системных служб
не выполняются. Основной эффект — свободное место на диске, а не
гарантированное уменьшение потребления оперативной памяти.

## Файлы и повторный запуск

Служебные загрузки (установщики FastPanel/Composer, архив Node.js), временный
каталог root, ответы, журнал и контрольные отметки находятся в
`/root/laiot-installer`, права каталога `0700`. Пароли и итоговые параметры —
в `access.txt`, права `0600`. Журнал `details.log` также доступен только root:
он может содержать диагностический вывод сторонних утилит, публиковать его
без проверки нельзя. Доступы FastPanel видны в SSH и сохраняются в этом
защищённом файле, если панель установил сам мастер; пароли готовой панели
мастер не получает и не меняет. Повторная активация лицензии не автоматизируется.

Памятка показывается перед веб-мастером и повторно в самом конце установки.
В итоговом варианте — адрес входа LaIOT, FastPanel, все пароли, созданные
Bash-мастером (панель, БД, MQTT при его выборе), адреса Redis/MQTT,
необязательный Zigbee2MQTT, пользователь приложения, пути к исходникам,
`.env`, файлам, журналам, кэшу, конфигурации и службам, команды проверки.
Повторный запуск обновляет справку с прежними паролями. Файл заменяется
атомарно и остаётся доступным только root; итоговый вывод идёт в SSH,
не в журнал этапов. Для повторного просмотра: `cat /root/laiot-installer/access.txt`.

Логин и пароль администратора LaIOT пользователь задаёт в веб-мастере:
Bash их не получает и восстановить из хеша не может. APP_KEY остаётся
в `.env`; памятка показывает путь к нему, не читая содержимое файла.
После завершения одноразовый ключ установки в памятку не включается.

Приложение и его сборка находятся в `<выбранный каталог>/current`;
`shared` подготовлен для шаблонов systemd. Сборка работает под выбранным
пользователем сайта, её собственные временные файлы
и кэши имеют права этого пользователя, не root. Zigbee2MQTT работает под
отдельным пользователем `zigbee2mqtt` в `/opt/zigbee2mqtt`.

При ошибке показывается этап и путь журнала. Запустите тот же скрипт снова:
завершённые этапы пропускаются, пароли сохраняются. Повторный запуск не
является обновлением и не должен использоваться для иной установки.
Готовая панель используется без переустановки, существующие данные
приложения и конфигурация другого агента автоматически не заменяются.
Не удаляйте каталог состояния для повторного
запуска на занятом сервере.

## Проверка и границы

Проверки в Linux не запускают APT, MySQL, Redis и внешние HTTP-запросы:

```bash
bash -n tools/install-server.sh
bash tests/server_installer_test.sh
php tests/docs_quality_smoke.php
```

Перед публичным распространением обязателен полный прогон на отдельной
чистой Ubuntu: установка и активация FastPanel, фактический PHP-FPM,
права nginx на `public`, локальный DNS, публичный HTTPS, веб-мастер,
перезагрузка служб, прерывание/продолжение и Zigbee с реальным координатором.
Дополнительно нужен прогон на сервере с готовой панелью, сайтом и
существующими пользовательскими данными. Проверки без сети в Linux-контейнере
подтверждают сценарии мастера с подменёнными командами, а не установку панели.

Официальные контракты:
[установка FastPanel](https://kb.fastpanel.direct/quick_start/how-to-install-fastpanel/),
[сайты CLI](https://kb.fastpanel.direct/cli/sites/),
[БД CLI](https://kb.fastpanel.direct/cli/databases/),
[локальные имена home.arpa](https://www.rfc-editor.org/info/rfc8375/),
[Zigbee2MQTT Linux](https://www.zigbee2mqtt.io/guide/installation/01_linux.html).
