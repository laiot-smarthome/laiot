# Консольные команды

Основной вход — `php bin/laiot`, Symfony Console. Команды зарегистрированы
в `app/Console/ConsoleFactory.php`, классы лежат в `app/Console/Commands`. Старый `php majordomo`,
`lib/core/Console` и `deploy.sh` удалены из ветки; обновление ядра ещё
проектируется. `bin/laiot-agent` — отдельный административный вход для systemd.

Для подготовки Ubuntu используется `bash deploy/setup-ubuntu.sh`.
Опция `--php-bin /usr/bin/php8.3` задаёт конкретный CLI PHP для проверок
и создаваемых юнитов; без неё выбирается PHP из `PATH`. Полный список
опций, умолчания и примеры — [системная установка](deploy.md).

Агент разрешает `core.*` для встроенных задач, включая `websocket`, полос
событий и существующих `module.<id>`. `worker.install` только проверяет установленные root-юниты;
обновить их можно системным установщиком от root. Протокол и права —
[права агента](deploy.md#права-агента-и-сокет).

## Проверки и просмотр

| Команда | Что проверяет или показывает |
| --- | --- |
| `about` | Версия, PHP, пути и окружение приложения |
| `route:list [--json]` | Реестр маршрутов нового kernel |
| `module:list` | Обнаруженные SDK-модули, installed/enabled; не ядровые страницы |
| `module:validate` | Манифесты и совместимость SDK |
| `module:check [id] [--json]` | Legacy-вызовы в коде модулей; код 1 при находках |
| `db:status` | Применённые и ожидающие миграции |
| `health` | Доступность БД и кэша; код 0 только при успехе |
| `doctor` | PHP-расширения, timezone, доступность каталогов, БД и кэша |
| `queue:stats --queue=default [--json]` | Готовые, зарезервированные, failed |
| `queue:failed --queue=default --limit=50 [--json]` | Упавшие задания |
| `maintenance status` | Состояние файла обслуживания |
| `systemctl status laiot-core@websocket` | Состояние штатной WebSocket-службы ядра |

Команды используют конфигурацию текущей установки. Даже диагностические
`health`/`doctor` обращаются к БД и кэшу; roundtrip кэша кратковременно
пишет ключ. Это не автономные проверки без сервисов.

## Команды, меняющие состояние

| Команда | Эффект |
| --- | --- |
| `db:migrate` | Применяет миграции, меняет схему/данные |
| `install` | `install`-часть: `.env`, миграции, администратор; см. раздел ниже |
| `user:create <username> <name> <password> [--admin]` | Создаёт пользователя, объект Users и стандартную роль |
| `api:token <user_id> <name> [--ttl=<секунды>]` | Записывает и показывает токен |
| `maintenance on` / `maintenance off` | Создаёт/удаляет `var/maintenance.flag` |
| `cache:clear` | Очищает выбранное хранилище, включая worker-состояние |
| `queue:retry <id>` | Возвращает failed-задание к обработке |
| `module:install <id>` | Реестр, миграции и install/enabled hooks |
| `module:disable <id>` / `module:enable <id>` | Меняет состояние SDK-модуля |
| `module:remove <id> [--purge]` | Uninstall hook, реестр, права, ассеты и файлы модуля; `--purge` — таблицы и SQLite/data |
| `db:prune [--dry-run]` | Удаляет устаревшие данные, включая outbox websocket и тикеты, по `config/retention.php` |

Не запускайте эту таблицу как готовый скрипт на рабочей установке.
Перед первым пользователем применяются миграции ядра, включая класс Users.
`user:create --admin` задаёт `is_admin` и назначает роль `admin`, без флага —
роль `user`. Логин — 8–64 символа по правилам имени объекта; пароль — от
восьми символов со спецсимволом. Подробности — [authentication.md](authentication.md).
Пароль этой команды передаётся
аргументом процесса и может попасть в shell history; интерактивного скрытого
ввода пока нет. Токен также не следует сохранять в общих логах.

`db:prune --dry-run` ничего не меняет и показывает объём по разделам.
Для постоянной очистки нужен `core-worker maintenance`, а не разовый запуск.

Параметры не изобретаются: у `queue:retry` сейчас нет `--all`, у
`cache:clear` — выбора prefix, отдельной команды `queue:forget` нет.
Удаление failed доступно через сервис и `/jobs`.

## Запуск работы

| Команда | Когда завершится |
| --- | --- |
| `queue:work --queue=default [--once] [--max-jobs=0]` | При пустой очереди или лимите |
| `timeout:run` | После прохода созревших таймеров |
| `worker <id> --once` | После прохода включённых задач SDK-модуля |
| `worker <id>` | Постоянный цикл задач модуля до сигнала/ошибки |
| `core-worker queue [--once]` | Постоянная очередь default либо один шаг |
| `core-worker events [--once]` | Постоянная очередь событий свойства либо один шаг |
| `core-worker events.<n> [--once]` | Одна полоса очереди событий (например, `events.2`) |
| `core-worker module.<id> [--once]` | Доставка изменений свойств конкретному модулю |
| `core-worker system-events [--once]` | Системные события минуты, часа и дня |
| `core-worker timeouts [--once]` | Постоянные таймеры либо один проход |
| `core-worker maintenance [--once]` | Retention сразу и затем по `retention.interval` |
| `core-worker websocket` | Постоянный сервер WebSocket; `--once` не поддерживается |

Эти команды выполняют пользовательский или модульный код и могут иметь
его внешние эффекты. `--once` ограничивает цикл, а не делает операцию
безопасной симуляцией. Ошибка отдельного задания может быть записана в
журнал, не превращаясь в неуспешный exit code всей команды.

Обработчики и повторы — [queue.md](queue.md); Linux, pcntl, Redis и
systemd — [runtime.md](runtime.md). Запуск тестов без рабочих подключений
описан отдельно в [testing.md](testing.md).


## Полный справочник

Запускайте команды из каталога установки. Угловые скобки в примерах
обозначают значения, которые нужно заменить; квадратные — необязательные
аргументы. Блок кода копируется кнопкой «Копировать», ничего не запускается
из браузера. Полный синтаксис доступен через `help <команда>`.

Общие опции: `--help` (`-h`) — справка, `--version` (`-V`) — версия,
`--quiet` (`-q`) — тихий вывод, `--verbose` (`-v`, `-vv`, `-vvv`) — подробность,
`--ansi` / `--no-ansi` — цвет, `--no-interaction` (`-n`) — без вопросов,
`--silent` — без вывода. Опции конкретной команды приведены ниже.

### install

Установить LaIOT: база, кэш и администратор.

Команда делает то же, что страница `/install`: проверяет PHP, расширения,
права, подключение к БД и Redis, пишет `.env`, выполняет миграции и создаёт
администратора. После успеха появляется `var/installed.lock`, а ключ
`var/install.key` удаляется. Системную часть (systemd-юниты, права) делает
[deploy.md](deploy.md), а не эта команда.

| Параметр | Описание | Обязателен | По умолчанию |
| --- | --- | --- | --- |
| `--db-host` | Сервер MySQL/MariaDB | нет | 127.0.0.1 |
| `--db-port` | Порт базы данных | нет | 3306 |
| `--db-name` | Имя базы данных | нет | — |
| `--db-user` | Пользователь базы данных | нет | — |
| `--db-password` | Пароль базы данных | нет | — |
| `--db-create` | Создать базу, если её нет | нет | нет |
| `--cache-driver` | Кэш: redis или file | нет | redis |
| `--redis-host` | Сервер Redis | нет | 127.0.0.1 |
| `--redis-port` | Порт Redis | нет | 6379 |
| `--redis-db` | Номер базы Redis | нет | 0 |
| `--redis-password` | Пароль Redis | нет | — |
| `--admin-login` | Логин администратора | нет | — |
| `--admin-name` | Имя администратора | нет | Администратор |
| `--admin-password` | Пароль администратора | нет | — |
| `--timezone` | Часовой пояс | нет | Europe/Moscow |

```bash
php bin/laiot install --db-name=laiot --db-user=laiot --db-password='...' \
  --db-create --admin-login=sysadmin --admin-name='Администратор' --admin-password='...'
```

Пароль в аргументах остаётся в истории оболочки. На сервере предпочтительнее
страница `/install`, команда нужна для восстановления доступа и автоматизации.
Повторный запуск на установленной системе отклоняется.

### update:status

Показать состояние обновления LaIOT без подключения к БД.

Собственных аргументов и опций нет. Выводит состояние и путь файла
аварийного ключа, без содержимого ключа.

```bash
php bin/laiot update:status
```

### release:build

Собрать готовый номерной релиз LaIOT.

| Параметр | Описание | Обязателен | По умолчанию |
| --- | --- | --- | --- |
| `tag` | Тег main-X.Y.Z или beta-X.Y.Z-beta.N | да | — |
| `--output` | Каталог готового архива и метаданных | нет | var/release |

GitHub Actions запускает после проверки кода, production Composer install
и сборки frontend. `.env`, var и сторонние модули не включаются.

```bash
php bin/laiot release:build beta-2.1.0-beta.1 --output /tmp/laiot-release
```

### Служебное автодополнение

Скрытая команда `_complete` используется оболочкой и не предназначена
для ручного запуска. Её параметры `--shell`, `--input`, `--current`,
`--symfony` и `--api-version` передаёт скрипт, созданный `completion`.

## Административный агент

`bin/laiot-agent` — отдельная точка входа для Linux/systemd, без Symfony
Console. `serve` (по умолчанию) слушает Unix-socket; `install` устанавливает
unit. Путь конфигурации задаётся `LAIOT_AGENT_CONFIG`, по умолчанию
`/etc/laiot/agent.json`. Схема и права описаны в [runtime.md](runtime.md).

```bash
php bin/laiot-agent serve
```

```bash
php bin/laiot-agent install
```

## Как поддерживать справочник

При добавлении, удалении или изменении команды обновляйте её описание,
аргументы, опции, значения по умолчанию и пример здесь в том же изменении.
Регистрация — `ConsoleFactory`, определения — `app/Console/Commands/*Command.php`.
`ConsoleDocumentationTest` сверяет этот справочник с реальным реестром,
не выполняя команды и не подключаясь к рабочим сервисам. Проверка входит
в PHPUnit и `composer check`. База знаний читает этот же Markdown.
