# LaIOT

LaIOT — отдельное приложение на PHP 8.2+ и компонентах Illuminate 12.
Это не полный Laravel: используются собственные Application, kernel,
сессии, очередь и модульный SDK. Код ядра лежит в `app/` по привычной
раскладке Laravel (контроллеры, middleware, модели, сервисы, провайдеры,
команды), интеграции — в `modules/`. Подробная карта —
[структура кода](architecture.md#структура-кода). Внешний вид панели
сохраняет дизайн alpha, реализация — Blade, Alpine и локальный бандл.

Справочник сверяется с текущим кодом; дорожная карта описывает будущую
работу. Зелёный исторический чекбокс не заменяет проверку сегодняшней сборки.
Актуальные границы сведены в [limitations.md](limitations.md).

## Что уже реализовано

- HTTP-вход `public/index.php`, контейнер, роутер, обработка ошибок,
  request ID, security headers и режим обслуживания. Браузерные 404/405/500/503
  получают отдельную страницу с маскотом, объяснением и кодом запроса.
  В debug исключение открывает страницу с исходником, трассировкой и
  копированием отчёта для ИИ. Ранний обработчик работает до Composer и boot.
- Вход администратора, проверка действующих сессий, CSRF, роли,
  API-токены и лимит попыток входа.
- Единый раздел «Классы»: дерево классов и подклассов, карточка класса,
  объекты, свойства и методы внутри неё; на ПК объекты — дочерние строки
  дерева, на телефоне — компактная панель класса. Системные имена —
  латиницей, с живой проверкой свободного имени; локация принадлежит
  объекту, а не классу. Значения и история живут у объекта. Отдельных
  пунктов меню для объектов, свойств, методов, значений и истории нет.
  Плюс страницы сценариев, пользователей, локаций, настроек, событий,
  очереди, журналов, webhook, уведомлений и UI Kit. У свойства видна политика
  повторов и привязки к модулям, а кнопка истории показывается только при
  включённой истории.
- Локации — дерево дом → этаж → комната. Комната автоматически получает
  объект в классе этажа (подкласс `Rooms`) и значения активности; свойства с
  ролью света, обогрева, охлаждения или датчика обновляют флаги комнаты, а
  таймер простоя вызывает `activity`/`nonActivity`. Хелперы `roomIsActive()`,
  `roomIsLight()`, `roomIsHeating()`, `roomIsCondition()` и `roomState()`
  читают состояние без запроса к UI. Подробности — [locations.md](locations.md).
- Переименование класса, объекта, свойства или метода обновляет ссылки в
  сценариях, методах, OnChange, webhook, таймерах, настройках и файлах
  модулей; подписки модулей хранят id и не отваливаются.
- WebSocket: отдельный сервер только на исходящие сообщения, короткоживущий
  тикет после входа администратора, подписка по якорям текущей страницы
  (`data-live-object`/`data-live-property`) в виде `Light.status`, снимок
  значений и системные события в канале `system`. Устройство —
  [websocket.md](websocket.md).
- Репозитории новой lowercase-схемы: наследование классов без ограничения
  глубины, объектные свойства/методы, история значений, асинхронный конвейер
  `property.changed` по полосам (OnChange, история; доставка модулям — в их
  очереди `module.<id>`) с защитой от повторения свойства в цепочке.
- История: выборка по периоду и агрегаты одним SQL (`HistoryQuery`), обёртки
  `history()`, `getHistoryAvg/Min/Max/Sum/Count`; `$this` в методе — контекст
  объекта с `get/set/history/call/notify`.
- Логи: каналы `app/http/security/queue/events` в отдельные файлы с суточной
  ротацией; у каждой записи `system_errors` свой файл с контекстом и trace,
  открывается из `/errors`. Retention чистит историю, журнал, упавшие
  задания, таймеры и ошибки по `config/retention.php` (`db:prune`,
  `core-worker maintenance`).
- CacheStore, долговечная очередь, именованные обработчики и таймеры
  (включая аренду таймера).
- Долговечное состояние цепочек свойств: порядок команд, ожидание родителя,
  отмена оставшихся действий при ошибке и продолжение этапов после сбоя;
  отдельный `core-worker module.<id>` для быстрой доставки привязок.
- SDK-модули: манифест, ModuleDb/ModuleBus, lifecycle, миграции, helpers,
  маршруты, фоновые задачи, права из манифеста, ассеты и purge; проверка
  legacy-вызовов `module:check`; пример `modules/example_sdk`. Core-модуль
  входит в поставку: его нельзя удалить, но можно выключить (MQTT).
- MQTT — core-модуль `modules/core/mqtt`: долгоживущее соединение с
  брокером, индекс привязок в памяти, приём в свойства через общий конвейер,
  отправка команд из очереди `module.mqtt`, журнал и Yoyo-страницы топиков.
  Устройство — [mqtt.md](mqtt.md).
- Zigbee — core-модуль `modules/core/zigbee` для Zigbee2MQTT на общем
  MQTT-соединении: обнаружение устройств и `exposes`, привязки к свойствам и
  методам с декларативными преобразованиями, обратная запись, комнаты,
  мониторинг доступности и батарей, журнал и Yoyo-страницы. Сообщение из
  MQTT-цикла превращается в задание `module.zigbee`; своего брокера нет.
  Устройство — [zigbee.md](zigbee.md).
- Настройки модулей из `module.json` с общим экраном
  `/admin/modules/<id>/settings` и подписки на свойства через
  `$context->subscriptions()`: модуль не подписывается за соседний и не
  рисует собственную форму параметров.
- Системные события минуты, часа и дня (`system.*`) и события модулей
  (`module.<id>.*`) с доставкой в очередях модулей и сценариев, привязанных
  к событию; сценарии хранят код без открывающего тега, синтаксис проверяется
  до сохранения, есть ручной запуск и режим без ядра.
- Worker модуля, отдельные процессы очереди/событий/таймеров и systemd-контроллер
  с административным Unix-socket агентом. Linux и live Redis проверяются
  отдельно от тестов на SQLite/array.
- Установка: страница `/install` с одноразовым ключом из `var/install.key`,
  проверкой PHP, прав, БД и Redis, записью `.env`, миграциями и первым
  администратором. Пока мастер не завершён, остальные страницы уводятся на
  `/install`, а API отвечает `503 not_installed`. Та же логика доступна
  командой `php bin/laiot install`. После установки `/install` отвечает 404.
  Руководство — [install.md](install.md).

Ядровые страницы живут в `app/Http/Controllers/Core` и
`resources/views/pages`, меню — в `CoreSections`. Они не являются
`modules/core`, не устанавливаются и не отключаются через SDK.
MQTT и Zigbee перенесены как встроенные модули `modules/core/mqtt` и
`modules/core/zigbee`; остальные внешние интеграции ещё переносятся.
Шаблонный каталог `modules/core` остаётся для SDK-модулей типа core, а не для
CRUD-страниц приложения.

## Что не следует считать готовым

Импорт данных из alpha, обновление с откатом, API v2/OpenAPI,
production-Docker, sandbox пользовательского PHP (проверка синтаксиса
перед сохранением — не sandbox), автоматическая выдача разрешений SDK и
полная совместимость сценариев alpha. `say()` сохраняет информационное
уведомление с важностью 0–10 и при достижении общего порога ставит
`system.say` подписчикам в фоновые очереди; источник определяется автоматически. Telegram,
push и речевой вывод ещё не реализованы. Контракт —
[уведомления](notifications.md). Конкретные ограничения — [здесь](limitations.md).

Старые `docs/agents`, `docs/user`, `docs/deploy` в основном описывают alpha.
Они могут объяснять происхождение дизайна или старый runtime, но не служат
готовой инструкцией развёртывания LaIOT. Alpha-runtime из этой ветки удалён;
его реализация остаётся в ветке `alpha`.

[Мастер-план](../todo/laiot.md) хранит этапы и принятые решения.
[Аудит админки и ядра 2026-10-29](production-audit.md) описывает исправления
состояния, цепочек, форм, токенов и оставшиеся проверки перед выпуском.
[Журнал аудита кода](core-audit.md) — датированный снимок проверки,
а не руководство по запуску. При изменении публичного поведения обновляйте
профильный документ и ссылки этого индекса вместе с кодом.

Объём и проверка последней переработки справочника —
[аудит документации](documentation-audit.md).
