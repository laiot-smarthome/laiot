# UI Kit LaIOT

Живые примеры находятся на `/ui-kit`. Blade-компоненты расположены в
`resources/views/components/md`; стили и скрипты входят в локальную сборку.
Alpha служит источником сценариев, но её PHP и JavaScript не используются.

В компонентах, попадающих в Yoyo, используйте полный синтаксис Alpine:
`x-on:click`, `x-on:keydown.escape.window`, `x-bind:class` и `x-bind:style`.
HTML-разборщик Yoyo удаляет сокращённые обработчики вида `@click`; в частности,
общий `x-md.modal` сохраняет обработчики закрытия и фокуса в полном синтаксисе.

## Оболочка и модули

Общий layout создаёт header, навигацию, основную область и диалоги. Разделы
ядра и SDK-модули передают содержимое через `PanelRenderer`, не создавая
собственных header или sidebar. Для вертикальных отступов используйте
`md-ui-page md-ui-page--stack`, для сеток — существующие `md-ui-card-grid`
и `md-ui-kpi-grid`. Цвета, радиусы и типографика берутся из `--md-ui-*`;
при необходимости добавить модульные стили держите их рядом с модулем.
У ссылок навигации активный пункт обозначается `aria-current`, на мобильном
экране меню закрывается по Esc и возвращает фокус кнопке открытия.

## Типографика и навигационная цепочка

`x-md.typography` задаёт размеры `display`, `h1`, `h2`, `h3`, `body`, `small`,
`caption` и `mono` через общие токены панели. Выбирайте заголовки по иерархии
страницы; атрибут `as` позволяет указать подходящий HTML-тег независимо от размера.

`x-md.breadcrumbs` принимает `items` с `label` и локальным `href`. Последний
пункт обозначает текущую страницу, имеет `aria-current="page"` и не является
ссылкой. Применяйте цепочку на вложенных страницах.

```blade
<x-md.typography variant="h2">Настройки устройства</x-md.typography>
<x-md.breadcrumbs :items="[
    ['label' => 'Панель', 'href' => '/admin'],
    ['label' => 'Классы', 'href' => '/classes'],
    ['label' => 'Датчики'],
]" />
```

## Ссылки

Ссылки в панели не подчёркиваются ни в покое, ни при наведении. Переход
показывают цвет, значок и смена оттенка или фона; пунктир оставлен только
для подсказки. Компонент — `<x-md.link href="...">Текст</x-md.link>`.

| Вариант | Когда использовать |
| --- | --- |
| `primary` (по умолчанию) | обычный переход внутри панели |
| `muted` | второстепенная ссылка рядом с основным действием |
| `subtle` | ссылка в заголовке или строке текста, наследует цвет |
| `danger` | необратимое действие, если кнопка слишком тяжёлая |
| `hint` | пояснение или подсказка: пунктирное подчёркивание |
| `action` | действие в строке текста или таблицы, не кнопка формы |

```blade
<x-md.link href="/classes">Классы</x-md.link>
<x-md.link href="/events" variant="action" icon="arrow-right">Открыть журнал</x-md.link>
<x-md.tooltip text="Изменения свойств доступны в карточке объекта.">
    <x-md.link href="#help" variant="hint">Как работает история</x-md.link>
</x-md.tooltip>
```

`icon` ставится перед текстом, `icon-after` — после. Внешняя ссылка
определяется по `http(s)://`: открывается в новой вкладке, получает
`rel="noopener noreferrer"` и значок `external-link`. Небезопасный `href`
(например, `javascript:`) не превращается в ссылку. `disabled` оставляет
текст, но убирает переход и добавляет `aria-disabled`.

Для формы и подтверждения используйте `x-md.button`: у кнопок нет
подчёркивания, в том числе когда кнопка является ссылкой. Не подчёркивайте
ссылки вручную и не добавляйте `text-decoration` в разметку.

## Маскот

Маскот выводится через `<x-md.mascot pose="sleep" />`; `pose` соответствует
имени PNG в `public/assets/img/maskot`. Все 19 образов представлены в разделе
«Маскот» UI Kit. Изображение декоративное (`alt=""`), смысл состояния передаёт
соседний текст. Для каталога используйте `loading="lazy"`.

Маскот уместен в пустом списке, поиске без результатов, приветствии на
главной, первом знакомстве с разделом и необязательной подсказке. Один образ
на блок, обычно один на экран: 64–88 px на главной, 120–150 px в пустом состоянии.
Рядом нужны короткий текст и полезное действие, если оно есть.

Не добавляйте его в плотные таблицы, поля форм, кнопки, каждую карточку или
каждый Notify. Безопасность и удаление требуют ясного объяснения и действия
без развлекательной иллюстрации. На страницах 404/405/500/503 допустим один
спокойный образ рядом с кодом, объяснением и действием: он не заменяет
причину, статус устройства, загрузку или подтверждение результата. `nothing` подходит для пустого списка, `sleep` — для отсутствия
новых событий, `find` — для поиска, `hello` — для приветствия, `love_home` —
для главной, `read` и `quest` — для справки. Все сценарии подписаны в живом
каталоге.

Страницы ошибок используют тот же принцип: 404 — `find`, 500 — `error`,
503 — `work`. Маскот стоит в одном блоке с кодом ответа; рядом видны
объяснение, путь, код запроса для 5xx и действие. Это не постоянная
анимация и не замена тексту ошибки.

Исключение при включённом debug использует диагностический экран без
маскота: логотип LaIOT, сообщение и исходник, раскрываемый стек, запрос и
кнопка «Скопировать для ИИ». Копирование использует общий Notify; его разметка
`components/md/toast-stack.php` доступна и без Blade. В обычной панели она
подключается через `x-md.toasts`, состояние задаёт общий `createToasts()`.

Изображения не анимируются постоянно и не мешают работе с данными. Проверяйте
светлую и тёмную темы; на узком экране уменьшайте маскота, сохраняя место тексту.

## Загрузка

`x-md.loader` использует общий `md-spinner`: `size="sm|md|lg"`, `block`
для центра области, `label` для скринридера. Видимая надпись не обязательна.
В UI Kit есть интерактивные примеры кнопки, поиска, drawer и скелетона блока;
локальная задержка в них нужна только для демонстрации.

- Первое открытие пустой области: большой лоадер на месте будущего содержимого.
- Поле: маленький индикатор справа; ввод остаётся доступным, устаревший ответ
  не заменяет результат нового запроса.
- Кнопка: индикатор рядом с подписью, повторное действие заблокировано.
- Обновление: сохраняйте данные и вращайте иконку обновления.
- Карточка или таблица с известной структурой: `x-md.skeleton` вместо данных
  только при первой загрузке. Не показывайте вместе несколько индикаторов
  одной операции внутри одной области.

Область запроса получает `aria-busy`, индикатор — `role="status"`. Снимайте
загрузку в `finally`, включая ошибку и отмену; предусматривайте повтор запроса.
Не задерживайте ответ ради анимации, не придумывайте проценты. При уменьшении
движения лоадер остаётся видимым, вращение отключается.

Уведомления показывают лоадер при открытии, сохраняют список при обновлении,
а после пустого ответа — `x-md.mascot-empty`: маскот, мягкий фон и короткое
описание. Пустое состояние не появляется до завершения запроса.

## Формы

`x-md.input`, `select`, `textarea`, `checkbox`, `radio`, `switch`, `range`,
`file-upload` и `choice-group` сохраняют нативные элементы формы. Параметры `label`,
`hint`, `error`, `required` и `disabled` задают подпись и состояние;
дополнительные атрибуты передаются контролу. Укажите уникальный `id`, если
на странице повторяются поля с одинаковым именем. Для пароля доступен
`password-toggle`.

```blade
<x-md.input name="title" label="Название" required :error="$error" />
<x-md.select name="rooms" label="Комнаты" :options="$rooms"
             :selected="$selected" searchable multiple />
<x-md.range name="brightness" label="Яркость" :value="60" unit="%" />
```

Tom Select работает локально и уничтожается вместе с элементом Alpine. При
отсутствии JavaScript остаётся обычный `select`. Выбранные значения формы
обязательно проверяются сервером.
`file-upload` показывает имена и размеры выбранных файлов, поддерживает
перетаскивание и удаление файлов из выбора; проверка типа и размера остаётся
на сервере.

`x-md.date-time-picker` принимает `type="date"` или `type="time"`, `name`,
`label` и значение в нативном формате (`YYYY-MM-DD` или `HH:MM`). Календарь и
выбор времени работают локально; при отключённом JavaScript остаётся обычное
поле браузера. Принимающий сервер проверяет значение самостоятельно.

## Таблицы и графики

Поиск `.md-table__search input` и селекты `.md-table__filter` используют
общую высоту `--md-ui-control-md` (36 px), как `md-input` и обычная кнопка.
В тулбаре на телефоне поля, фильтры и кнопки имеют минимум
`--md-ui-control-lg` (44 px). Не задавайте селекту отдельную уменьшенную
высоту на странице: общий стиль применяется ко всем таблицам.

`x-md.table` собирает серверную таблицу из слотов; для серверных поиска и
фильтров используйте Yoyo и сервис данных. `x-md.data-table` применяет
Tabulator к небольшому набору, уже переданному в HTML: поиск, сортировка и
пагинация выполняются в браузере. Скрывать чувствительные данные этим
способом нельзя. Ячейки отображаются как текст; без JS доступна обычная
таблица.

```blade
<x-md.data-table label="Устройства"
    :columns="[['key' => 'name', 'label' => 'Устройство']]"
    :rows="$rows" :page-size="10" />
```

`x-md.chart-card` и `x-md.sparkline` принимают `points` с числовыми `t` (Unix-время в
миллисекундах) и `v`, а также `title` и `unit`. График ApexCharts грузится
отдельным чанком; таблица данных остаётся доступна без JavaScript.

## Диалоги и действия

У `x-md.modal` есть фиксированные варианты ширины `size="sm|md|lg|xl"`:
300, 500, 800 и 1140 px. По умолчанию — `md`; неизвестный размер также
приводится к `md`. На узком экране ширина ограничена доступным местом с
отступами 12 px. Размер не вычисляется по длине текста.
Подтверждения используют `md` и общий класс `md-modal--confirm`: высота
240 px, ограниченная высотой экрана, тело прокручивается, заголовок и
кнопки остаются на месте. Формы в обычных модалках сохраняют естественную
высоту. Все размеры и короткое/длинное подтверждение доступны в `/ui-kit`.

`x-md.modal` и `x-md.drawer` открываются через `$store.mdModal.show(id)` и
`$store.mdDrawer.show(id)`. При открытии фокус переходит внутрь, Tab остаётся
в диалоге, Esc закрывает его и возвращает фокус. `x-md.dropdown` содержит
обычные ссылки и кнопки. Его панель — нативный popover в верхнем слое:
таблица не обрезает меню. `align="right"` выравнивает его по правому краю,
`icon-only` оставляет кнопку со значком и доступным именем из `label`.
Стрелка вниз открывает меню и переводит фокус к пунктам; стрелки вверх/вниз,
Home/End перемещают фокус, Esc закрывает меню. Модальные окна и панели
блокируют прокрутку фона; закрытая панель поиска исключена из обхода Tab.
`x-md.tooltip` показывает текст при наведении и
фокусе на вложенном интерактивном элементе.
`history-drawer` принимает содержимое слотом, `trace-drawer` — дерево `nodes`;
источник данных и право доступа определяет вызывающий компонент. Для реальной
истории свойства используйте существующий Yoyo `property-history`.

`x-md.call-flow` сохраняет семантическое дерево шагов и веток. Соединения
рисует SVG по фактическим центрам значков и меток веток; переносы текста,
сворачивание, открытие подробностей и изменение размера вызывают пересчёт.
Наведение и клавиатурный фокус выделяют весь путь к выбранному шагу.
Кнопки «Свернуть всё» и «Развернуть всё» управляют только своей схемой.
Кнопки веток доступны скринридеру; декоративные значки и SVG скрыты от него.

`x-md.command-palette` принимает `id` и `items` с `label`, `description`,
`href`; разрешены только локальные пути и якоря. `x-md.context-menu` принимает
слот `trigger` и содержимое меню; открывается правой кнопкой или Shift+F10.
`x-md.icon-browser` загружает локальный каталог Tabler и копирует имя класса.
После обновления пакета иконок каталог пересоздаётся командой `npm run icons`.

Уведомление можно показать вызовом
`$store.mdToasts.push({title, text, tone, duration})`; `duration: 0` оставляет
его до закрытия. Возможные тона: `info`, `success`, `warning`, `danger`.

## Умный дом и составные блоки

Карточки `device-card`, `room-card`, `sensor`, `light-control`, `thermostat`,
`scene-card`, `cycle-card`, `energy-widget`, `meter`, `automation-row`,
`connection-status` и `last-seen` выводят переданные данные. Они не управляют
устройствами автоматически: форма или Yoyo-компонент страницы проверяет права,
проверяет значения и вызывает сервис ядра. Аналогично `entity`, `entity-text`
и `call-flow` отображают сущности и дерево вызовов; входящие данные не
становятся кодом. `entity-text` распознаёт метки вида
`[[property:Kitchen.Temperature|Температура]]`, остальной текст экранируется.
`call-flow` показывает время, условия и выполненные или пропущенные ветки.
Узел также может содержать `actor`, `before`, `after`, `detail` и `payload`;
эти данные передаёт вызывающая сторона, компонент не восстанавливает их сам.
`max-depth` ограничивает вложенность дерева (по умолчанию 24, максимум 128).
В «Событиях» передаётся 128, чтобы длинная цепочка не обрезалась в интерфейсе.

`x-md.code` с PHP-кодом подсвечивает синтаксис без открывающего тега,
показывает подсказки по клавишам и предварительные синтаксические ошибки.
Параметр `error` принимает `['line' => N, 'message' => '…']` от серверного
валидатора: над редактором появляется текст со строкой, `aria-invalid`
ставится на поле, а CodeMirror переводит курсор на эту строку. Проверка в
браузере остаётся предварительной; сохранение разрешает только серверная
проверка PHP. `x-md.code-sample` показывает код только для чтения и
копирования, поддерживает подсветку `php`, `javascript` и `json`.
`x-md.json-view` форматирует переданные данные как JSON. Без JavaScript
текст остаётся доступным без подсветки.

`x-md.object-tree` принимает `items` с `label`, необязательными `icon`,
локальной ссылкой `href`, `children` и `open`. Ветки раскрываются через
нативный `details`. Журнал событий с серверными фильтрами уже реализован в
Yoyo-компоненте `events-table` и доступен на `/events` и в UI Kit.

`@yoyo('folder-picker', ['name' => 'path'])` выбирает серверный каталог внутри
корня проекта. Требуется `settings.manage`; скрытые каталоги, `vendor`,
`node_modules` и символьные ссылки исключены. Путь в отправленной форме
остаётся пользовательским вводом: принимающий его сервер обязан проверить и
разрешение, и допустимые границы пути.
Каталоги выбираются в диалоге с фильтром; во время перехода показывается
индикатор загрузки.

`@yoyo('script-categories')` — модальное управление категориями сценариев.
При открытии виден список; «Добавить» и карандаш в строке заменяют контент
формой, сохранение возвращает список. Компонент сам рисует кнопку и нативный
`<dialog>`, действия идут через `yoyo:get`/`yoyo:post`, подтверждение удаления
встроено в строку, а `window.confirm()` не используется. Изменяющие действия
идут POST с CSRF; оболочка добавляет `X-CSRF-Token` к запросам Yoyo из
meta-тега страницы.

## Notify — сообщения об операциях

Результаты действий в админке показываются только через Notify.
Обычный серверный шаблон использует:

```blade
<x-md.notify type="success" title="Сохранено" text="Настройки обновлены." />
<x-md.notify type="danger" title="Не сохранено" :text="$error" />
```

Yoyo отправляет событие из серверного компонента:

```php
$this->dispatchBrowserEvent('md:notify', ['tone' => 'success', 'text' => 'Сохранено']);
```

Оболочка передаёт событие в тот же Notify. При обычном POST с редиректом
используйте `PanelRenderer::redirect($url, $text, $tone)`; сообщение
хранится в сессии и забирается один раз. `PanelRenderer::notify()` добавляет
сообщение без редиректа. Текст уведомлений запрещено передавать через
GET-параметры; обновление страницы не должно повторять сообщение.

Локальное действие Alpine использует тот же стек:

```javascript
$store.mdToasts.push({tone: 'success', title: 'Готово', text: 'Модуль включён.'})
```

Тоны: `success`, `info`, `warning`, `danger`. Стек закреплён снизу справа;
на телефоне занимает доступную ширину с безопасным нижним отступом.
Все тона автоматически скрываются через 7 секунд. `duration` в миллисекундах
переопределяет срок, `0` явно отключает автозакрытие. Тонкая полоса снизу
показывает оставшееся время; наведение и фокус независимо приостанавливают
таймер и полосу. Появление и закрытие плавные; при уменьшении движения
переход отключается.
Совпадающие видимые сообщения не дублируются. Кнопка закрытия доступна
с клавиатуры, ошибки объявляются через `role=alert`, остальные — `status`.

Новое уведомление сопровождает мягкий импульс по краям экрана на 280 мс.
Он не сдвигает страницу, не перехватывает фокус и клики. Общий ограничитель
разрешает не больше одного импульса в секунду; пропущенные импульсы не
накапливаются. При `prefers-reduced-motion: reduce` анимация отключена.

Не добавляйте дублирующий баннер результата в контенте. Поле с ошибкой
сохраняет своё сообщение и `aria-invalid`; постоянное состояние страницы
(например, обслуживание) и справочные блоки могут использовать `x-md.alert`.
Секреты и выданные токены показываются в отдельной карточке с копированием.
Notify не записывает события в центр уведомлений с колокольчиком.
Живые примеры четырёх состояний находятся в `/ui-kit`, «Диалоги».

## Проверка изменений интерфейса

Запустите `npm run build`, изолированные PHPUnit-тесты UI Kit и Yoyo,
`php tests/docs_quality_smoke.php` и `composer check`. В браузере проверяйте
светлую и тёмную темы, узкий экран, клавиатуру и состояния ошибок. Новые
компоненты снабжайте живым примером и документируйте их параметры здесь.
