# MyDoMo: мастер-план

Статус: **ядро готово к переписыванию модулей**. Ветка создана от `alpha`;
alpha-runtime из неё удалён и остаётся в ветке `alpha` как источник истории.

## 1. Принципы

- Совместимость с alpha не цель: берём смысл функции, а не её сигнатуры,
  флаги и таблицы.
- Модули — SDK-пакеты (`modules/<id>`), ядровые страницы — `src` + Blade.
  Integration-код не растворяется в ядре.
- Запись свойства асинхронна: значение + задание `property.changed` в одной
  транзакции; OnChange, история и доставка — в `core-worker events`.
- Подписки на свойства выбирает пользователь; манифест объявляет только
  обработчик и схему настроек.
- Модуль не блокирует ядро: доставка идёт в `module.<id>`, задачи — в
  `worker <id>`.
- Один процесс на полосу событий; порядок изменений одного свойства
  сохраняется.
- Коммит делается только по просьбе; код, документация и план меняются
  вместе.

## 2. Что уже работает

- HTTP-вход `public/index.php`, контейнер, роутер, ошибки, request ID,
  security headers, maintenance.
- Вход, сессии, CSRF, роли, права, API-токены, лимит попыток входа.
- Модель дома: классы с подклассами, объекты, свойства/методы с
  наследованием, значения, история и агрегаты, `$this` в методах.
- Локации: дерево дом → этаж → комната, автоматические класс `Rooms`,
  подкласс этажа и объект комнаты, роли свойств, таймер простоя и
  `activity`/`nonActivity`; хелперы `roomIsActive()` и соседние.
- Асинхронный конвейер свойств: полосы `events.<n>`, журнал, OnChange,
  защита от циклов и эха.
- Доставка модулям через `module.<id>`; SDK-подписки и настройки из
  `module.json`, общий экран `/admin/modules/<id>/settings`.
- Системные события минуты, часа и дня (`system.*`) и события модулей
  (`module.<id>.*`): доставка в очередях модулей и запуск привязанных
  сценариев через очередь `default`.
- Сценарии: проверка синтаксиса до сохранения, ручной запуск с результатом,
  режим без ядра отдельным php-процессом.
- Очередь: повторы, failed/dead-letter, резервации, таймеры с арендой.
- SDK: манифест, ModuleDb/ModuleBus, миграции, helpers, маршруты, права,
  ассеты, purge, `module:check`. Core-модуль входит в поставку: удалять
  нельзя, выключать можно (строка реестра).
- MQTT — core-модуль `modules/core/mqtt`: одно долгоживущее соединение,
  индекс привязок в памяти, приём в свойства через общий конвейер, отправка
  команд из `module.mqtt`, журнал, Yoyo-страницы и helpers
  `mqtt_publish`/`mqtt_value`/`mqtt_connected`. Настройки — в таблице
  модуля, потому что реестр настроек для core закрыт. Устройство —
  [mqtt.md](../mydomo/mqtt.md).
- Логи по каналам и отдельный файл на ошибку; просмотр файла в админке.
- Ошибки: два Yoyo-экрана — список групп/записей и детали с периодом
  повторов, местом, стеком, контекстом, raw-файлом и копированием для AI.
- Retention: `db:prune`, `core-worker maintenance`, сроки в
  `config/retention.php`.
- Веб-панель: обзор, классы/объекты, сценарии, события, очередь, журналы,
  пользователи, роли, настройки, модули, API/webhook, уведомления,
  обслуживание, UI Kit.
- Боковое меню: группы-аккордеоны с каталогами «Диагностика», «API и доступ»,
  «Сервис», бейджи ошибок/очереди/непрочитанных и живое обновление через
  `/api/v1/panel/attention`; на ПК панель сворачивается до иконок.

## 4. Решения

- 2026-10-26 — сначала закрываем ядро, затем модули; UI не переделываем.
- 2026-10-27 — установка/обновление не блокируют релиз, API отложен.
- 2026-10-27 — подписки выбирает пользователь, не манифест.
- 2026-10-27 — доставка модулям изолирована в `module.<id>`.
- 2026-10-27 — настройки модулей — схема в манифесте + общий экран.
- 2026-10-27 — core-модуль можно выключить, но нельзя установить или
  удалить. Выключение — строка `module_registry` с `enabled=0`, а не
  отдельный флаг в манифесте. Общий экран настроек SDK для core закрыт:
  MQTT хранит параметры подключения в своей таблице и проверяет их
  `ModuleSettings::cast()`.
- 2026-10-27 — MQTT-интерфейс реактивный через Yoyo: `mqtt-topics` и
  `mqtt-status` перерисовываются `/yoyo`, отдельного JSON-эндпоинта нет.
  Автообновление значений — событие `mqtt-refresh` раз в 5 секунд, пока
  фокус не в поле компонента.
- 2026-10-27 — alpha-runtime удалён; установщик, API v2 и Docker-стенд
  делаются заново на новом ядре.
- 2026-10-27 — сценарий запускается по системному событию, а не по
  расписанию: планировщик по-прежнему отдельная задача.
- 2026-10-27 — категории сценариев живут в модалке Yoyo, не отдельной
  страницей и не блоком на главной.
- 2026-10-27 — пользовательский PHP проверяется синтаксически до
  сохранения; это проверка, а не sandbox.
- 2026-10-27 — события принадлежат владельцу: ядро отправляет `system.*`,
  модуль — `module.<id>.*`.
- 2026-10-27 — сценарий по умолчанию работает с ядром; отключение ядра
  даёт обычный php-процесс без обёрток, но не sandbox.
- 2026-10-27 — ручной запуск сценария отпускает блокировку сессии, чтобы
  вкладки не ждали; очередь событий пока последовательная.
- 2026-10-27 — лимиты запусков не выводятся из настроек пула FPM: это
  внешний статический предел, а не свободные процессы. При необходимости
  задаём свой `scripts.max_concurrent`.
- 2026-10-27 — целевой веб-слой — nginx + PHP-FPM; локальный Docker-стенд
  собран так же, Apache и mod_php не используются.
- 2026-10-27 — системные имена классов, объектов, свойств и методов —
  только латиница, цифры и `_`: по ним строятся `setGlobal()`,
  `getGlobal()` и вызовы методов. Уникальность проверяется в репозитории и
  живо подсвечивается в форме.
- 2026-10-27 — локация принадлежит объекту: класс не получает `location_id`,
  а дерево и карточка объекта показывают его помещение.
- 2026-10-27 — на ПК объекты видны дочерними строками дерева классов; на
  телефоне — компактной панелью под классом, чтобы не уводить иерархию
  вправо.
- 2026-10-27 — переименование имени каскадное: код сценариев/методов/webhook,
  OnChange, настройки, ссылки-значения и файлы модулей обновляются вместе с
  записью; подписки модулей остаются по id. История и журнал не переписываются.
- 2026-10-27 — повторная запись свойства по умолчанию запускает цепочку;
  галочка `only_new_values` принимает повтор, но не запускает OnChange,
  историю и модули. Карточка свойства показывает подписки и обработчики.
- 2026-10-27 — комната — объект в классе этажа (подкласс `Rooms`); имя
  объекта транслитом, при совпадении добавляется `_2`. Локация хранит
  ссылки на класс и объект, но по-прежнему принадлежит объекту.
- 2026-10-27 — активность комнаты считается по таймеру после последнего
  изменения роль-свойства; включённый свет без событий не держит её вечно.
  Таймер — штатная запись `runtime_timeouts`, на комнату одна.
- 2026-10-27 — тип и родитель локации задаются при создании; перенос
  комнаты между этажами остаётся отдельной операцией.
- 2026-10-27 — меню — нативные `details/summary`, а не Alpine: аккордеон
  работает без JavaScript, а `sidebar.js` только запоминает раскрытые ветки.
  Счётчики внимания считает `PanelAttention`; оболочка обновляет их через
  `/api/v1/panel/attention`, страницы остаются серверными.
