# MyDoMo: мастер-план

Статус: **ядро готово к переписыванию модулей**. Ветка создана от `alpha`;
alpha-runtime из неё удалён и остаётся в ветке `alpha` как источник истории.

## 1. Принципы

- Совместимость с alpha не цель: берём смысл функции, а не её сигнатуры,
  флаги и таблицы.
- Модули — SDK-пакеты (`modules/<id>`), ядровые страницы — `src` + Blade.
  Integration-код не растворяется в ядре.
- Запись свойства асинхронна: значение + задание `property.changed` в одной
  транзакции; OnChange, история и доставка — в `core-worker events`.
- Подписки на свойства выбирает пользователь; манифест объявляет только
  обработчик и схему настроек.
- Модуль не блокирует ядро: доставка идёт в `module.<id>`, задачи — в
  `worker <id>`.
- Один процесс на полосу событий; порядок изменений одного свойства
  сохраняется.
- Коммит делается только по просьбе; код, документация и план меняются
  вместе.

## 2. Что уже работает

- HTTP-вход `public/index.php`, контейнер, роутер, ошибки, request ID,
  security headers, maintenance.
- Вход, сессии, CSRF, роли, права, API-токены, лимит попыток входа.
- Модель дома: классы с подклассами, объекты, свойства/методы с
  наследованием, значения, история и агрегаты, `$this` в методах.
- Асинхронный конвейер свойств: полосы `events.<n>`, журнал, OnChange,
  защита от циклов и эха.
- Доставка модулям через `module.<id>`; SDK-подписки и настройки из
  `module.json`, общий экран `/admin/modules/<id>/settings`.
- Очередь: повторы, failed/dead-letter, резервации, таймеры с арендой.
- SDK: манифест, ModuleDb/ModuleBus, миграции, helpers, маршруты, права,
  ассеты, purge, `module:check`.
- Логи по каналам и отдельный файл на ошибку; просмотр файла в админке.
- Retention: `db:prune`, `core-worker maintenance`, сроки в
  `config/retention.php`.
- Веб-панель: обзор, классы/объекты, сценарии, события, очередь, журналы,
  пользователи, роли, настройки, модули, API/webhook, уведомления,
  обслуживание, UI Kit.

## 3. Что осталось

- [ ] Установщик нового ядра: браузерный мастер и `mydomo:install`.
- [ ] Обновление с release-каталогами, проверкой версии и откатом.
- [ ] API v2/OpenAPI и единый конверт ответов.
- [ ] Импорт данных из alpha как отдельная операция (не runtime-адаптер).
- [ ] Таймеры: счётчик попыток и failed-политика.
- [ ] Решение по планировщику (задания по дате/расписанию).
- [ ] Метрики очередей и health для фоновых процессов.
- [ ] Подкаталог в URL и внешняя маршрутизация CRUD webhook.

### Модули

Порядок: MQTT → Zigbee → pinghosts → modes → market → ai_assistant → xray →
saverestore. Каждый переносится целиком: манифест, настройки, подписки,
worker, миграции, тесты, docs. Старый код берётся из `alpha` только как
справка.

### Интерфейс

UI-переработка отложена владельцем. До неё сохраняется текущий alpha-визуал
на Blade/Alpine/Yoyo.

## 4. Решения

- 2026-10-26 — сначала закрываем ядро, затем модули; UI не переделываем.
- 2026-10-27 — установка/обновление не блокируют релиз, API отложен.
- 2026-10-27 — подписки выбирает пользователь, не манифест.
- 2026-10-27 — доставка модулям изолирована в `module.<id>`.
- 2026-10-27 — настройки модулей — схема в манифесте + общий экран.
- 2026-10-27 — alpha-runtime удалён; установщик, API v2 и Docker-стенд
  делаются заново на новом ядре.

## 6. Проверка

- Код: `composer check` (parallel-lint, PHP-CS-Fixer dry-run, PHPStan,
  PHPUnit Feature).
- Документация: `php tests/docs_quality_smoke.php`.
- Frontend: `node --check resources/js/app-mydomo.js`, `npm run build`.
- Docker: `docker compose up --build -d`, панель на `http://127.0.0.1:8080`.

Результаты последнего прогона фиксируются здесь датой, а не «зелёным
чекбоксом» без проверки. Перед релизом нужен прогон на Linux с MySQL,
Redis, pcntl и systemd.
