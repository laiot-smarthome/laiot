# UI Kit MyDoMo

Живые примеры находятся на `/ui-kit`. Blade-компоненты расположены в
`resources/views/components/md`; стили и скрипты входят в локальную сборку.
Alpha служит источником сценариев, но её PHP и JavaScript не используются.

## Оболочка и модули

Общий layout создаёт header, навигацию, основную область и диалоги. Разделы
ядра и SDK-модули передают содержимое через `PanelRenderer`, не создавая
собственных header или sidebar. Для вертикальных отступов используйте
`md-ui-page md-ui-page--stack`, для сеток — существующие `md-ui-card-grid`
и `md-ui-kpi-grid`. Цвета, радиусы и типографика берутся из `--md-ui-*`;
при необходимости добавить модульные стили держите их рядом с модулем.
У ссылок навигации активный пункт обозначается `aria-current`, на мобильном
экране меню закрывается по Esc и возвращает фокус кнопке открытия.

## Формы

`x-md.input`, `select`, `textarea`, `checkbox`, `radio`, `switch`, `range`,
`file-upload` и `choice-group` сохраняют нативные элементы формы. Параметры `label`,
`hint`, `error`, `required` и `disabled` задают подпись и состояние;
дополнительные атрибуты передаются контролу. Укажите уникальный `id`, если
на странице повторяются поля с одинаковым именем. Для пароля доступен
`password-toggle`.

```blade
<x-md.input name="title" label="Название" required :error="$error" />
<x-md.select name="rooms" label="Комнаты" :options="$rooms"
             :selected="$selected" searchable multiple />
<x-md.range name="brightness" label="Яркость" :value="60" unit="%" />
```

Tom Select работает локально и уничтожается вместе с элементом Alpine. При
отсутствии JavaScript остаётся обычный `select`. Выбранные значения формы
обязательно проверяются сервером.

## Таблицы и графики

`x-md.table` собирает серверную таблицу из слотов; для серверных поиска и
фильтров используйте Yoyo и сервис данных. `x-md.data-table` применяет
Tabulator к небольшому набору, уже переданному в HTML: поиск, сортировка и
пагинация выполняются в браузере. Скрывать чувствительные данные этим
способом нельзя. Ячейки отображаются как текст; без JS доступна обычная
таблица.

```blade
<x-md.data-table label="Устройства"
    :columns="[['key' => 'name', 'label' => 'Устройство']]"
    :rows="$rows" :page-size="10" />
```

`x-md.chart-card` и `x-md.sparkline` принимают `points` с числовыми `t` (Unix-время в
миллисекундах) и `v`, а также `title` и `unit`. График ApexCharts грузится
отдельным чанком; таблица данных остаётся доступна без JavaScript.

## Диалоги и действия

`x-md.modal` и `x-md.drawer` открываются через `$store.mdModal.show(id)` и
`$store.mdDrawer.show(id)`. При открытии фокус переходит внутрь, Tab остаётся
в диалоге, Esc закрывает его и возвращает фокус. `x-md.dropdown` содержит
обычные ссылки и кнопки. `x-md.tooltip` показывает текст при наведении и
фокусе на вложенном интерактивном элементе.
`history-drawer` принимает содержимое слотом, `trace-drawer` — дерево `nodes`;
источник данных и право доступа определяет вызывающий компонент. Для реальной
истории свойства используйте существующий Yoyo `property-history`.

`x-md.command-palette` принимает `id` и `items` с `label`, `description`,
`href`; разрешены только локальные пути и якоря. `x-md.context-menu` принимает
слот `trigger` и содержимое меню; открывается правой кнопкой или Shift+F10.
`x-md.icon-browser` загружает локальный каталог Tabler и копирует имя класса.
После обновления пакета иконок каталог пересоздаётся командой `npm run icons`.

Уведомление можно показать вызовом
`$store.mdToasts.push({title, text, tone, duration})`; `duration: 0` оставляет
его до закрытия. Возможные тона: `info`, `success`, `warning`, `danger`.

## Умный дом и составные блоки

Карточки `device-card`, `room-card`, `sensor`, `light-control`, `thermostat`,
`scene-card`, `cycle-card`, `energy-widget`, `meter`, `automation-row`,
`connection-status` и `last-seen` выводят переданные данные. Они не управляют
устройствами автоматически: форма или Yoyo-компонент страницы проверяет права,
проверяет значения и вызывает сервис ядра. Аналогично `entity`, `entity-text`
и `call-flow` отображают сущности и дерево вызовов; входящие данные не
становятся кодом. `entity-text` распознаёт метки вида
`[[property:Kitchen.Temperature|Температура]]`, остальной текст экранируется.

`@yoyo('folder-picker', ['name' => 'path'])` выбирает серверный каталог внутри
корня проекта. Требуется `settings.manage`; скрытые каталоги, `vendor`,
`node_modules` и символьные ссылки исключены. Путь в отправленной форме
остаётся пользовательским вводом: принимающий его сервер обязан проверить и
разрешение, и допустимые границы пути.

## Проверки

Запустите `npm run build`, изолированные PHPUnit-тесты UI Kit и Yoyo,
`php tests/docs_quality_smoke.php` и `composer check`. В браузере проверяйте
светлую и тёмную темы, узкий экран, клавиатуру и состояния ошибок. Новые
компоненты снабжайте живым примером и документируйте их параметры здесь.
