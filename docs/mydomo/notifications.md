# Центр уведомлений

Результаты действий пользователя (сохранение, включение модуля, ошибка
операции) показываются через всплывающий Notify. Контракт и примеры —
[в UI Kit](ui-kit.md). Эти сообщения не записываются в таблицу
`notifications` и не увеличивают счётчик колокольчика.

Уведомление — короткое сообщение модуля или сценария, которое ждёт внимания
администратора: запись в БД, колокольчик в шапке и drawer в админке.
`say()` также ставит событие сообщения системы подписчикам в фоновые очереди,
если важность сообщения достигает общего порога доставки.

## 1. Таблица `notifications`

| Поле | Смысл |
| --- | --- |
| `module` | код модуля (`events`, `mqtt`, `system`) |
| `type` | `info`, `success`, `warning`, `danger` |
| `message` | короткий текст, 1–255 символов |
| `importance` | важность 0–10, по умолчанию 5; не заменяет цветовой `type` |
| `title`, `details` | необязательные заголовок и подробности |
| `url`, `label` | внутренняя ссылка (`/...`) и текст кнопки |
| `notification_key` | ключ дедупликации для повторяющихся событий |
| `read_at` | время явного прочтения; `null` — непрочитанное |

`notifications` создаётся миграцией `2026_10_26_000020_create_notifications.php`.
Миграция `2026_10_29_000001_add_notification_importance.php` добавляет
важность существующим установкам; прежние записи получают уровень 5.
Непрочитанные строки не удаляются автоматически; прочитанные остаются для
истории. Отдельного retention пока нет.

## 2. Сервис `NotificationService`

```php
use MajorDoMo\Notifications\NotificationService;

$service = $app->container()->make(NotificationService::class);

$result = $service->send('events', 'Цикл остановлен', 'warning', [
    'key' => 'chain:KitchenLight.temperature',
    'title' => 'Цепочка события',
    'details' => 'Повтор свойства в цепочке',
    'url' => '/events',
    'label' => 'Открыть журнал',
]);
// ['status' => true, 'id' => 12]
```

Правила:

- `module` — строчные латинские буквы, цифры, `_`, `-`; для системных
  сообщений используется `system`;
- сообщение очищается от HTML; пустое или длиннее 255 символов отклоняется;
- `type` нормализуется: `default` → `info`, `error`/`fail` → `danger`,
  `warn` → `warning`, `ok` → `success`;
- `url` — только внутренний абсолютный путь (`/...`), внешние схемы и `//`
  отклоняются;
- повтор того же источника с тем же `key` (или тем же текстом и типом)
  в пределах окна возвращает `status=false` и `id` последней записи с
  равной или большей важностью; повышение уровня создаёт новую запись;
- понижение после повышения не обходит защиту: учитываются все равные или
  более важные записи того же уведомления в пределах окна;
- окно отсчитывается от последней сохранённой записи, по умолчанию час;
  прочтение не отменяет подавление, игнорируемые повторы не продлевают окно;
- ровно после истечения окна повтор снова сохраняется, даже если прежнее
  уведомление не прочитано; лимита 10 непрочитанных больше нет;
- `notifications.duplicate_window` в `config/notifications.php` задаёт
  секунды; `0` отключает подавление. Окружение —
  `NOTIFICATIONS_DUPLICATE_WINDOW`, панель — «Настройки → Уведомления».

Выборки:

```php
$service->listing();                 // total, counts, levels, severity, items, offset
$service->listing('events', 50);     // только модуль, вторая страница
$service->summary();                 // total, counts, levels, severity
$service->dismiss(12);               // прочитать одно
$service->dismiss(null, 'events');   // прочитать все непрочитанные модуля
```

`items` — до 50 записей, сначала `danger`/`warning`, затем свежие. Поле
`module_url` ведёт в ядровой раздел (`CoreSections`) или `/module/<id>` для
модуля; для `system` — `/admin`. Каждый элемент содержит `importance`.
Прямой `send()` принимает важность пятым аргументом, по умолчанию 5;
значения вне целочисленной шкалы 0–10 отклоняются общим валидатором.

## 3. Обёртка `notify()`

Для сценариев и методов есть простая системная обёртка:

```php
notify('Датчик на кухне не отвечает', 'warning', [
    'key' => 'sensor:kitchen',
    'url' => '/errors',
]);
```

`notify()` пишет от модуля `system`, возвращает результат
`NotificationService::send()`: `status`, `id` или `error`.

### Сообщение системы через `say()`

```php
$result = say('Входная дверь открыта');
say('Датчик не отвечает', 10);
say('Промежуточное состояние', 4);
```

Сигнатура: `say(string $message, int $importance = 5): array`.
Шкала важности — 0–10. Источник задавать не нужно: `SaySource` определяет
ближайший вызывающий модуль по файлам SDK и использует его ID; для
сценариев — `scripts`, методов — `methods`, PHP-webhook — `webhooks`,
остального кода ядра — `system`. Вложенный вызов модуля из сценария получает
ID модуля, а метод, запущенный сценарием, — `methods`. Стек читается без
аргументов функций; состояние между вызовами не сохраняется.

Общий порог — `notifications.minimum_importance` в `config/notifications.php`,
по умолчанию 5. Окружение — `SAY_MINIMUM_IMPORTANCE`, панель —
«Настройки → Уведомления → Минимальная важность say». Шкала порога — 0–10:
при 0 подходят все сообщения, при 10 — только максимальная важность.
Долгоживущие процессы читают настройку при запуске и требуют перезапуска.
Старых параметров громкости и пользователя нет. Запись и постановку
доставки выполняет `SayService`.

Принятое сообщение сохраняется как `info` с числовой важностью. При
`importance < minimum_importance` оно остаётся только в журнале. При
`importance >= minimum_importance` публикуется `system.say` с данными:

| Поле события | Смысл |
| --- | --- |
| `id` | ID сохранённого уведомления |
| `source` | Источник сообщения |
| `message` | Сохранённый текст без HTML |
| `type` | `info` |
| `importance` | Числовая важность 0–10 |
| `created_at` | Время записи в часовом поясе приложения |

Модуль подписывается при загрузке через существующий SDK:

```php
$context->onSystemEvent('system.say', function (string $event, array $data): void {
    // Здесь модуль реализует доставку: $data['message'], $data['id'].
});
```

Обработчик запускается в `module.<id>` worker'ом получателя. Сценарий
также может указать `system.say` как событие запуска. Запись журнала и
задания подписчиков сохраняются в одной транзакции: ошибка постановки
откатывает оба. Подавленный повтор, невалидный текст или важность ниже
порога не создают событие. Повышение важности обходит подавление повторов,
но доставка всё равно требует достижения порога.
`notify()` и прямой `send()` события `system.say` не публикуют.

Возврат `status=true, id` подтверждает запись и постановку заданий, если
важность достигла порога, а не доставку пользователю. Для сообщения ниже
порога это подтверждение записи в журнал. Повтор возвращает `status=false, id, error`, другая
ошибка — `status=false, error`. Доставка очередью допускает повторное
выполнение: модуль может использовать `id` для своей дедупликации.
Telegram, push и речевой вывод пока не реализованы; событие даёт им общую
точку подключения. Это не ретроспективная рассылка старых записей модулям,
подключённым позже.

## 4. API админки

```text
GET  /api/v1/panel/notifications?module=<id>&offset=<n>
POST /api/v1/panel/notifications/dismiss     {"id": 12}
POST /api/v1/panel/notifications/dismiss     {"module": "events"}
```

GET требует сессию администратора, POST — ещё и заголовок `X-CSRF-Token`
(страница передаёт его из `meta[name="csrf-token"]` через `MDJAdminApi`).
Ответ — конверт `{ok, data}`; у `dismiss` в `data` лежит `dismissed`.

## 5. Колокольчик и drawer

В `layouts.alpha` есть:

- кнопка `[data-md-notifications-open]` с бейджем
  `[data-md-notifications-count]` в шапке;
- общий drawer `#mdAdminDrawerHost` (`resources/js/mydomo/drawer.js`);
- скрытый блок `#mdNotificationsContent` (`resources/js/mydomo/notifications.js`),
  который переносится в drawer при открытии.

Открытие списка не считается прочтением: запись скрывается только после
кнопки «Прочитано» (или явного `dismiss`). JS обновляет счётчик при загрузке,
при возврате на вкладку и раз в минуту; WebSocket-толка для уведомлений пока
нет.

## 6. Чего пока нет

Отдельная ядровая страница `/notifications` уже существует:
`src/Http/Controllers/Core/NotificationsPageController.php` и
`resources/views/pages/notifications/index.blade.php`. Она показывает
непрочитанные записи и принимает POST `/notifications/{id}/dismiss` с CSRF.
Это не история всех прочитанных уведомлений.

- push по WebSocket для обновления панели;
- страницы истории прочитанных уведомлений и retention;
- per-module блоков в карточках модулей (API уже отдаёт `counts`/`levels`);
- ограничения прав: уведомления видит любой вошедший в админку.
