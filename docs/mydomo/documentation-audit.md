# Аудит документации MyDoMo

Аудит выполнен после переноса ядровых разделов из modules/core в src и
Blade-страницы. Источники: routes, CoreSections, bootstrap/ConfigSchema,
реализации сервисов и CLI текущей ветки; исходная точка — изменения
7cae516e и последующий снимок 0fc94650. Изменялась только документация,
не код приложения, окружение или рабочие сервисы.

## Что исправлено

- Разделены ядровые страницы и SDK-интеграции. Старые инструкции упаковывать
  users/objects/API в core-модули больше не определяют текущую архитектуру.
- Карта панели переведена на реальные чистые URL. Старые адреса остались
  только в явно историческом контексте и описании отсутствующих aliases.
- CLI описан по фактическим классам и параметрам, включая различие
  разового queue:work, постоянного core-worker и tasks SDK-модуля.
- Убраны обещания единого конверта API, автоматического CodeGuard,
  объектного `$this`, универсального soft-delete и очистки любого кэша
  только по префиксу. Вместо них описано реальное поведение.
- Уточнены сроки lock, fork/timeout, роль Redis и реальное состояние
  установки systemd-агента. План обновления отделён от рабочих команд.
- Shoutbox больше не учебный пример. say описана как запись info-
  уведомления через NotificationService, без обещания речи/терминала.
- Исправлены метаданные базы знаний, ссылки на старые JS-модули уведомлений,
  описание схемы, соединения SDK-миграций и фактические настройки Config.
- Мастер-план получил актуальную трактовку и явную маркировку ранних
  вариантов; исторические результаты аудита кода не выданы за новый прогон.

## Обновлённые файлы

В docs/mydomo: README.md, AGENTS.md, architecture.md, functions.md,
modules.md, sdk.md, runtime.md, database.md, testing.md,
events.md, notifications.md, knowledge_base.md, core-audit.md и этот журнал.

Входные точки: корневой AGENTS.md, docs/README.md, docs/todo/README.md и
docs/todo/mydomo.md. Старые справочники alpha не переписывались целиком;
навигация явно отделяет их от нового приложения.

Новый `admin-ui.md`, подготовленный при переносе интерфейса, включён в
навигацию README и карту разделов; его описание компонентов не дублируется
в архитектурном справочнике.

## Что осталось задачами кода

Расхождение APP_TIMEZONE/ConfigSchema, внешняя маршрутизация CRUD webhook,
резервные права Authorization, проверка владельца API-токена, длительные
worker-lock и прочие детали не исправлялись документацией. Для них
существует отдельный [перечень ограничений](limitations.md), на который
ссылаются соответствующие руководства. Наличие этого списка не заменяет
регрессионные тесты и последующую реализацию.

Полный runtime-набор и Docker в рамках этой задачи не запускались:
они не проверяют истинность текста вместо сверки с источниками и могут
обращаться к сервисам. Структура и примеры проверяются отдельно.

## Выполненные проверки

- `php tests/docs_quality_smoke.php` — успешно: метаданные, язык и
  относительные ссылки всего дерева документации.
- 21 PHP-пример проверен через `php -l` без исполнения кода; отдельный
  пример метода проверялся в синтаксическом контексте класса.
- 8 JSON-примеров успешно разобраны парсером.
- 26 URL из таблицы ядровых разделов найдены в текущем routes/web.php.
- `git diff --check` не обнаружил ошибок пробелов/конфликтных маркеров.

Это проверка документации, а не новый отчёт о PHPUnit, live Redis или
запуске приложения на production-сервисах.
