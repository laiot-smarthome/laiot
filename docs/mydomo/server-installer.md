# Подготовка сервера по SSH

`tools/install-server.sh` — публикуемый Bash-файл для чистой Ubuntu 24.04
x86_64 с systemd. Запускать только под пользователем root. Доступ в интернет
нужен для установки пакетов и активации FastPanel; белый IP для домашней
установки не требуется. Ubuntu 26 пока не включена: поддержку нужно сверить
с официальным установщиком FastPanel и проверить на отдельном стенде.

Скачайте файл с сайта распространения в `/root/install-server.sh`, затем
запустите в интерактивном SSH-сеансе:

```bash
bash /root/install-server.sh
```

Параметр `--help` показывает справку и не меняет систему. Других параметров
нет: выбор делается вопросами с ответами по умолчанию. Адрес публикации
файла ещё не определён; команда скачивания должна использовать HTTPS.
Не запускайте загруженный файл, не проверив его источник и содержимое.

## Порядок работы

1. Проверка root, Ubuntu и отсутствия прежней серверной установки.
2. Выбор локального или публичного сайта, имени и IPv4 интерфейса сервера.
   Отдельные вопросы — Mosquitto, доступ MQTT из домашней сети,
   Zigbee2MQTT и очистка предустановленных программ. По умолчанию эти
   компоненты и очистка выключены.
3. После подтверждения — необязательная очистка, установка FastPanel,
   показ адреса панели и нового случайного пароля `fastuser`. Пользователь
   активирует лицензию по email и устанавливает PHP 8.3 для сайтов в панели.
4. Установка PHP CLI 8.3 и расширений, Redis на loopback, Node.js 24 LTS
   из официального архива с проверкой SHA-256, Composer с проверкой подписи
   его установщика. Node.js доступен через `/usr/local/bin`.
5. Создание сайта и БД через `mogwai`, получение приложения из
   `https://github.com/laiot-smarthome/laiot.git`, ветка `beta`. Для будущего
   перехода поменять `BRANCH=main` в начале скрипта. Повторный запуск
   использует сохранённую ветку, а не обновляет приложение.
6. Установка зависимостей через Composer и сборка `npm ci` / `npm run build`
   под владельцем сайта. Подготовка systemd-агента и шаблонов worker.
7. Настройка корня сайта, обработки адресов и HTTPS в FastPanel по подсказкам.
   Мастер проверяет, что `/install` отвечает HTTP 200. Параметры корня сайта
   не меняются через недокументированные API панели.
8. Показ ссылки, одноразового ключа и параметров подключения. Пользователь
   завершает [веб-установщик](install.md) и возвращается в SSH. Только после
   появления `var/installed.lock` мастер запускает основные фоновые процессы.
   После успешного запуска он повторно выводит полную памятку для сохранения.

Сам SSH-мастер не пишет `.env`, не выполняет миграции и не создаёт
администратора MyDoMo: это задача веб-интерфейса. Выберите в нём Redis,
базу `mydomo_app`, пользователя `mydomo_app`, сервер `127.0.0.1` и показанный
пароль. Снимите флажок создания базы — она уже создана панелью.

## Локальный сайт

Предлагается `mydomo.home.arpa`. Установщик показывает запись для DNS роутера
или файла `hosts` каждого клиентского устройства. Сам он не меняет роутер
и не открывает порты наружу. До настройки DNS использует прямую проверку
сайта через выбранный IP и HTTP Host. Локальный сайт открывается по HTTP;
доверенный локальный сертификат можно настроить отдельно в FastPanel.

Для публичного сайта нужен собственный домен, DNS, доступные 80/443 и
сертификат в панели; проверка HTTPS не отключает проверку доверия сертификату.

## Необязательные компоненты

Mosquitto требует случайный пароль, анонимный доступ выключен. По умолчанию
он слушает loopback. Для частного IPv4 мастер предлагает дополнительно
слушать именно адрес домашней сети. Файрвол и маршрутизатор автоматически
не перенастраиваются. Параметры брокера затем указываются в модуле MQTT.

Zigbee2MQTT ставится отдельно от SDK-модуля MyDoMo, зафиксирована версия
2.14.2. Версия pnpm берётся из её `packageManager`. Настройка координатора
выполняется через собственный мастер Zigbee2MQTT: он слушает `127.0.0.1:8080`,
SSH-мастер показывает команду туннеля с компьютера пользователя. Если
Mosquitto не выбран, запрашивается адрес существующего MQTT-брокера;
его пароль вводится в интерфейсе Zigbee2MQTT. Настройка и проверка Zigbee
не блокируют первую установку MyDoMo.

Очистка рассматривает только установленный LibreOffice, Thunderbird,
Rhythmbox, Shotwell, Simple Scan, Transmission GTK, Totem, Cheese,
GNOME Tour и игры Aisleriot/Mahjongg/Mines/Sudoku. Сначала APT вычисляет
список удаления. Если он включает пакет вне этого списка, очистка
отменяется. Перед реальным удалением пользователь видит точные имена
пакетов и подтверждает его отдельно; отказ продолжает установку.
`autoremove`, удаление Snap, рабочего стола, SSH, сети и системных служб
не выполняются. Основной эффект — свободное место на диске, а не
гарантированное уменьшение потребления оперативной памяти.

## Файлы и повторный запуск

Служебные загрузки (установщики FastPanel/Composer, архив Node.js), временный
каталог root, ответы, журнал и контрольные отметки находятся в
`/root/mydomo-installer`, права каталога `0700`. Пароли и итоговые параметры —
в `access.txt`, права `0600`. Журнал `details.log` также доступен только root:
он может содержать диагностический вывод сторонних утилит, публиковать его
без проверки нельзя. Доступы FastPanel видны в SSH и сохраняются в этом
защищённом файле; повторная активация лицензии не автоматизируется.

Памятка показывается перед веб-мастером и повторно в самом конце установки.
В итоговом варианте — адрес входа MyDoMo, FastPanel, все пароли, созданные
Bash-мастером (панель, БД, MQTT при его выборе), адреса Redis/MQTT,
необязательный Zigbee2MQTT, пользователь приложения, пути к исходникам,
`.env`, файлам, журналам, кэшу, конфигурации и службам, команды проверки.
Повторный запуск обновляет справку с прежними паролями. Файл заменяется
атомарно и остаётся доступным только root; итоговый вывод идёт в SSH,
не в журнал этапов. Для повторного просмотра: `cat /root/mydomo-installer/access.txt`.

Логин и пароль администратора MyDoMo пользователь задаёт в веб-мастере:
Bash их не получает и восстановить из хеша не может. APP_KEY остаётся
в `.env`; памятка показывает путь к нему, не читая содержимое файла.
После завершения одноразовый ключ установки в памятку не включается.

Приложение и его сборка находятся в
`/var/www/mydomo_usr/data/mydomo/current`; `shared` подготовлен для шаблонов
systemd. Сборка работает под `mydomo_usr`, её собственные временные файлы
и кэши имеют права этого пользователя, не root. Zigbee2MQTT работает под
отдельным пользователем `zigbee2mqtt` в `/opt/zigbee2mqtt`.

При ошибке показывается этап и путь журнала. Запустите тот же скрипт снова:
завершённые этапы пропускаются, пароли сохраняются. Повторный запуск не
является обновлением и не должен использоваться для иной установки.
Посторонняя существующая панель, данные приложения и конфигурация агента
автоматически не заменяются. Не удаляйте каталог состояния для повторного
запуска на занятом сервере.

## Проверка и границы

Локальные проверки не запускают APT, MySQL, Redis и внешние HTTP-запросы:

```bash
bash -n tools/install-server.sh
bash tests/server_installer_test.sh
php tests/docs_quality_smoke.php
```

Перед публичным распространением обязателен полный прогон на отдельной
чистой Ubuntu: установка и активация FastPanel, фактический PHP-FPM,
права nginx на `public`, локальный DNS, публичный HTTPS, веб-мастер,
перезагрузка служб, прерывание/продолжение и Zigbee с реальным координатором.
Синтаксическая проверка на Windows этого не подтверждает.

Официальные контракты:
[установка FastPanel](https://kb.fastpanel.direct/quick_start/how-to-install-fastpanel/),
[сайты CLI](https://kb.fastpanel.direct/cli/sites/),
[БД CLI](https://kb.fastpanel.direct/cli/databases/),
[локальные имена home.arpa](https://www.rfc-editor.org/info/rfc8375/),
[Zigbee2MQTT Linux](https://www.zigbee2mqtt.io/guide/installation/01_linux.html).
