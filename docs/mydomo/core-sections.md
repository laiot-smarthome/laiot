# Ядровые разделы панели

Классы (вместе с объектами), пользователи, API и журналы теперь являются
частью приложения.
У них нет `module.json`, ModuleDb, install/uninstall hooks и возможности
отключения через `module:disable`. Меню задаёт `src/Panel/CoreSections.php`.
SDK-модули добавляют собственные пункты отдельно.

## Карта страниц

Все страницы таблицы требуют браузерного входа; изменение данных требует
CSRF. Дополнительные разрешения отмечены там, где они заданы маршрутом.

| URL | Раздел | Что делает |
| --- | --- | --- |
| `/admin` | Обзор | Главная страница панели |
| `/status` | Состояние | Информация о приложении, БД и кэше |
| `/classes` | Классы | Дерево классов, подклассов и объектов: на ПК объекты — дочерние строки, на телефоне — панель; карточка с вкладками «Основное», «Свойства», «Методы», «Объекты» |
| `/objects/{id}/edit` | Класс → объект | Карточка объекта: имя, класс, расположение, значения, объектные свойства/методы, история и журнал |
| `/locations` | Локации | Дерево дом → этаж → комната, приоритет, число объектов и список; комната получает класс/объект и активность, локация принадлежит объекту, не классу |
| `/scripts` | Скрипты | Список сценариев, запуск по системному событию, категории в модалке, импорт/экспорт |
| `/events` | События | Шаги цепочки свойства и состояние обработчиков |
| `/jobs` | Очередь | Состояние заданий, retry/удаление failed |
| `/knowledge-base` | База знаний | Эти Markdown-документы с поиском |
| `/users` | Пользователи и роли | Учётные записи, роли и разрешения в одном разделе, объекты Users; `can:users.manage` |
| `/settings` | Настройки | Редактор `.env` по схеме, вкладки и пояснения; `can:settings.manage` |
| `/journal` | Журнал действий | Аудит входов и действий пользователей |
| `/errors` | Ошибки | Yoyo-экран из двух режимов: список групп/записей и отдельные детали — когда, где, число повторов, стек, контекст, raw-файл, копирование для AI |
| `/notifications` | Оповещения | Список уведомлений и отметка прочтения |
| `/api` | Входящие webhook | Настройка секретов и обработчиков |
| `/admin/api` | API-документация | Список зарегистрированных API-маршрутов |
| `/admin/tokens` | API-токены | Выпуск/отзыв; `can:users.manage` |
| `/admin/modules` | Модули | Состояние и описание обнаруженных SDK-модулей |
| `/admin/maintenance` | Обслуживание | Управление флагом; `can:settings.manage` |
| `/admin/profile` | Профиль | Имя и пароль текущего администратора |
| `/ui-kit` | UI Kit | Компоненты Blade/Alpine и демонстрация Yoyo |

Поведение разделов, вкладки и новые компоненты подробно описаны в
[admin-ui.md](admin-ui.md); этот документ хранит карту URL и границы слоёв.

`/properties/create`, `/properties/{id}/edit`, `/methods/create` и
`/methods/{id}/edit` — контекстные формы класса или объекта, а не разделы
меню. Каталогов `/properties`, `/methods`, `/values` и `/history` больше
нет: значения и история открываются у объекта. `/objects` без `id`
перенаправляет в `/classes`, потому что вход в модель дома — класс.
Системные имена всех четырёх сущностей — латиница, цифры и `_`; уникальность
и живая подсветка в форме описаны в [admin-ui.md](admin-ui.md).

`GET /` и `/login` показывают форму входа. `/health` и часть API доступны
без сессии, поэтому они вынесены в [api.md](api.md).

## Меню и каталоги

Состав меню задаёт `CoreSections`. С 2026-10-27 это не один длинный список
«Системы», а группы с вложенными каталогами:

| Группа | Пункты и каталоги |
| --- | --- |
| Обзор | Обзор, Состояние |
| Дом | Классы, Локации |
| Автоматизация | Скрипты, События, Очередь, База знаний |
| Система | Модули, Пользователи и роли, Настройки; каталоги «Диагностика» (Журнал, Ошибки), «API и доступ» (API и webhooks, документация, токены), «Сервис» (Оповещения, Обслуживание, UI Kit) |
| Интеграции | страницы SDK-модулей из `ModuleManager::menuItems()` |

`CoreSections::structure()` отдаёт группы и каталоги без оформления,
`CoreSections::prepare()` добавляет ключи раскрытия и бейджи, а
`CoreSections::activeKeys()` находит группу и каталог текущей страницы.
Разметка — нативные `details/summary`, поэтому меню раскрывается и без
JavaScript. Модуль добавляет свои пункты прежним способом: через манифест
`menu`, отдельная группа «Интеграции» собирается в `PanelRenderer`.

В `CoreSections::all()` поле `group` — это id группы (`overview`, `home`,
`automation`, `system`), а не подпись; человеческий текст даёт
`CoreSections::groupLabel()`. Так поиск по панели и отчёты не зависят от
формулировок в меню.

Профиль не является пунктом меню: он живёт в подвале боковой панели вместе
с кнопкой выхода.

### Счётчики внимания

`PanelAttention` считает то, что требует реакции: ошибки за последние сутки,
задания с ошибкой в очереди и непрочитанные уведомления. Бейджи приходят
готовыми в разметку (включая нулевые), сумма группы считается на сервере и
пересчитывается в браузере. Живое обновление — `GET /api/v1/panel/attention`
раз в 90 секунд; это виджет оболочки, страницы по-прежнему считают данные на
сервере. Подробности — [admin-ui.md](admin-ui.md).

## Где находится реализация

- Регистрация ядровых маршрутов — `routes/web.php` и `routes/api.php`.
- Большинство CRUD-контроллеров — `src/Http/Controllers/Core/`.
- Обработчики webhook — `src/Api/Webhooks/`.
- Представления разделов — `resources/views/pages/<section>/`;
  общая оболочка — `resources/views/layouts/alpha.blade.php`.
- Данные и доменная логика — репозитории/сервисы `src/Objects`,
  `Properties`, `Methods`, `Scripts`, `History`, `Notifications` и другие.
- `PanelRenderer` + `PanelPage` собирают общий layout и меню.

Имя layout `alpha` означает визуальное происхождение дизайна, а не
подключение старого шаблонизатора. UI работает через Blade, Alpine и
локальные `mydomo.js`/`mydomo.css`. Компоненты `x-md.*` находятся в
`resources/views/components/md`; страницы не должны подключать jQuery,
Bootstrap JS или CDN-библиотеки отдельно от бандла.

## Как добавить ядровую страницу

1. Определить, что это действительно универсальная часть приложения.
   Интеграция устройства/поставщика остаётся SDK-модулем.
2. Добавить контроллер, получающий сервисы через DI, и Blade-представление.
3. Зарегистрировать маршрут с `auth`, необходимым `can:` и CSRF для записи.
4. Добавить пункт `CoreSections`, если страница должна быть в меню.
5. Проверить основной HTTP-сценарий в изолированной SQLite и обновить
   профильный документ. Внешний дизайн сохраняется, внутренний код — новый.

Это описание текущей архитектуры, не требование снова упаковывать страницы
в `modules/core`. Старые `/module/objects`, `/module/users`,
`/module/knowledge_base`, `/panel/...` не являются aliases новых страниц;
редиректов для них не добавляем. Префикс `/module/<id>` остаётся SDK-модулям.

Удаление Shoutbox означает, что `/module/shoutbox` больше не раздел панели.
Обёртка `say()` теперь делегирует информационное сообщение в центр
уведомлений; её границы описаны в [functions.md](functions.md).
