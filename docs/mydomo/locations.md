# Локации и активность комнат

Локации — это справочник дома: **дом → этаж → комната**. Дом и этаж
объединяют помещения, а комната остаётся местом, к которому привязаны
объекты. Дерево нужно для будущей свёртки по этажу и для группировки
объектов; сама логика свёртки пока не реализована.

## Иерархия и типы

После сохранения активной комнаты панель пересчитывает её таймер. Если
пересчёт не удался, настройки остаются сохранёнными, ошибка записывается
в журнал, а Notify явно предупреждает о необновлённом таймере. Ошибка чтения
состояния или источников не подменяется пустым списком.

| Тип | Код | Родитель | Что создаётся |
| --- | --- | --- | --- |
| Дом | `house` | верхний уровень | только класс `Rooms` |
| Этаж | `floor` | дом или верхний уровень | класс `Rooms` и подкласс этажа |
| Комната | `room` | этаж, дом или верхний уровень | класс комнаты и объект комнаты |

Тип и родитель задаются при создании. Перенос комнаты на другой этаж —
отдельная операция: вместе с `parent_id` нужно перепривязать класс, объект и
значения, поэтому форма редактирования их не меняет. Название локации может
быть кириллицей; системные имена класса/объекта — только латиница.

## Автоматическая модель комнаты

При создании локации ядро готовит модель дома через `RoomProvisioner`:

1. Класс `Rooms` создаётся один раз. В нём появляются свойства
   `isActive`, `isLight`, `isHeating`, `isCondition`, `activityTimeout`,
   `lastActivityAt` и методы-хуки `activity`, `nonActivity`.
2. Если у комнаты есть этаж, для этажа создаётся класс — подкласс `Rooms`
   с транслитерированным названием. Один класс этажа используется всеми
   комнатами этажа.
3. Комната получает объект с транслитерированным названием. Объект лежит в
   классе этажа (или в `Rooms`, если этажа нет), а `objects.location_id`
   указывает на локацию комнаты.
4. У объекта сразу создаются значения: активность выключена, свет/обогрев/
   кондиционер выключены, `activityTimeout` взят из локации,
   `lastActivityAt` пуст.

Транслитерация: `Спальня` → `Spalnya`, `Первый этаж` → `Pervyy_etazh`,
`Кухня` → `Kukhnya`. Системные имена объектов уникальны во всей установке,
поэтому вторая «Спальня» получает `Spalnya_2`. Локация хранит ссылку на
свой объект (`locations.object_id`), поэтому хелперы ищут комнату по
названию локации, а не по угаданному имени объекта.

У класса нет `location_id`: локация по-прежнему принадлежит объекту. Ссылки
`locations.class_id` и `locations.object_id` — служебные, они нужны только
для автоматической модели комнаты.

## Роли свойств

Активность собирается не с комнаты, а с оборудования в ней. В карточке
свойства задаётся **роль в комнате**:

| Роль | Что означает | Куда попадает |
| --- | --- | --- |
| `light` | свет | `isLight` |
| `heating` | обогрев | `isHeating` |
| `cooling` | кондиционер / охлаждение | `isCondition` |
| `sensor` | датчик активности | только таймер |

Роль доступна только у свойства объекта, который расположен в комнате.
У классового свойства локации нет, у объекта в доме или на этаже — тоже;
в этих случаях поле заблокировано и показывает подсказку с причиной. Если
объект перенести в комнату, роль снова можно выбрать. Уже сохранённая роль
при заблокированном поле не стирается: правка названия или описания её
сохраняет.

Если роль не сохраняется, проверьте миграции: `php bin/mydomo db:status` и
`php bin/mydomo db:migrate`. Колонка `properties.room_role` и поля иерархии
локаций появляются миграцией; без них запись роли невозможна. Начиная с
этой версии ядро возвращает ошибку вместо молчаливого пропуска.

Система просматривает объекты с `location_id` комнаты, находит действующие
свойства с ролью (с учётом класса, подклассов и объектных переопределений) и
читает их значения. Активным считается непустое значение, кроме `0`,
`false`, `off`, `no`, `none`, `disabled`, `closed`; для чисел — любое
ненулевое.

Свойства самой комнаты роль не получают: иначе `isActive` продлевал бы
активность сам себя.

### Когда меняется состояние

Любое изменение свойства с ролью:

- продлевает активность на `activityTimeout` секунд (по умолчанию 900);
- пересчитывает `isLight`, `isHeating`, `isCondition`;
- при переходе из неактивной в активную вызывает метод комнаты `activity`;
- ставит (переставляет) таймер простоя.

Комната считается активной, пока после последнего изменения роль-свойства
прошло меньше `activityTimeout`. Это выбор владельца: даже включённый свет
без новых событий перестаёт держать комнату активной по истечении срока.
Флаги света/обогрева/кондиционера при этом остаются текущими.

По истечении таймера `isActive` становится `0` и вызывается метод
`nonActivity`. Повторное событие, пришедшее после срабатывания таймера,
снова включает комнату и вызывает `activity`.

Повторная запись того же значения не считается новым изменением и таймер не
продлевает; для сенсоров, которые присылают повтор, это ограничение нужно
учитывать. Политика `only_new_values` у свойства дополнительно гасит цепочку
повтора.

## Таймеры

Таймер — штатная запись `runtime_timeouts` с именем
`room.activity.<id локации>`. На комнату одна активная запись: новое событие
снимает старую и ставит новую. Код таймера вызывает
`RoomActivityService::expire()`; тот перечитывает `lastActivityAt`, поэтому
просроченный таймер не выключает комнату, активность которой уже продлили.

Выполняет таймеры процесс `core-worker timeouts` или разовая команда
`php bin/mydomo timeout:run`. Если процесс не запущен, значения активности
обновятся при изменении свойств, но завершение по простою не сработает.
Устройство очереди и таймеров описано в [queue.md](queue.md).

Правка `activityTimeout` в локации или в свойстве комнаты пересчитывает
таймер: увеличение срока не оставляет комнату «зависшей» активной.

## Хелперы

Для сценариев и методов доступны короткие проверки:

```php
$active = roomIsActive('Кухня');       // локация или объект комнаты
$light = roomIsLight('Kukhnya');
$heating = roomIsHeating('Кухня');
$condition = roomIsCondition('Кухня');

$state = roomState('Кухня');
// location_id, title, object_id, object_title,
// active, light, heating, condition, timeout, last_activity_at
```

Неизвестная комната даёт `null` для `roomState()` и `false` для проверок.
Если названия локаций совпадают (две «Спальни» на разных этажах), передайте
системное имя объекта комнаты: `Spalnya_2`. Подробности и другие обёртки —
[functions.md](functions.md).

## Ограничения

- Хуки `activity`/`nonActivity` объявлены у класса `Rooms`. Ядро не разрешает
  одноимённые методы в подклассах и у объектов, поэтому реакцию настраивают
  в базовом методе; внутри можно ветвиться по названию комнаты.
- Удалить дом или этаж с вложенными локациями нельзя: сначала удаляются
  или переносятся дети. При удалении комнаты её автоматический объект
  архивируется, а остальные объекты отвязываются от локации.
- Существующие до миграции локации получают тип `room`, но объект комнаты
  им не создаётся автоматически. Для новой автоматической модели создайте
  комнату заново или подготовьте объект вручную.
- `isCondition` — историческое имя флага кондиционера; в интерфейсе он
  подписан как «Кондиционер».

`RoomProvisioner.php`, `RoomActivityService.php`, `RoomRole.php`.
Страницы — `/locations` и `/locations/{id}/edit`.
