# Первая установка

Установка делится на две части. Приложение ставит веб-мастер `/install`
(или команда `php bin/mydomo install`): проверяет окружение и подключения,
пишет `.env`, выполняет миграции и создаёт первого администратора. Системную
часть — пользователя, права, systemd-юниты и агент — делает
[deploy.md](deploy.md). Одна часть не заменяет другую: база без служб
работает, но история, OnChange и доставка модулям отстают.

Страница установки не требует настроенной базы: приложение открывает
соединение лениво, поэтому до появления `DB_NAME` bootstrap не обращается
к MySQL. Это то же правило, по которому страница ошибок рисуется без БД.

Пока мастер не завершён, любые браузерные страницы — `/`, `/login`,
`/admin`, разделы панели — перенаправляются на `/install`. Исключения:
сама страница установки, `/health`, `/api/v1/health` и статика; API вместо
редиректа получает `503` с кодом `not_installed`. Признак завершения —
`var/installed.lock`; если lock потерян, но в базе есть администратор,
маркер восстанавливается автоматически.

## Что нужно на сервере

- Ubuntu и FastPanel с сайтом, корень которого указывает на `public`;
- PHP 8.2+ под отдельным пользователем сайта, расширения `pdo_mysql`,
  `mbstring`, `intl`, `curl`, `openssl`; для фоновых процессов — `pcntl`,
  `posix`;
- MySQL/MariaDB и, для рабочей установки, Redis;
- каталог установки, доступный на запись пользователю PHP-FPM;
- для служб — `systemd` и административный агент (см. [runtime.md](runtime.md)).

Nginx и PHP-FPM настраиваются в FastPanel. Приложение не читает и не меняет
их конфигурацию: сайт должен отдавать `public/index.php`, статику — из
`public/assets`.

Если сервер поднимается с нуля, сначала пройдите
[интерактивный SSH-мастер](server-installer.md): он ставит FastPanel, PHP,
Redis, сайт и зависимости. Затем вернитесь к этой странице — мастер доводит
приложение до рабочего состояния.

## Веб-мастер

Мастер пошаговый: каждый шаг проверяет свои поля и не пускает дальше, пока
ошибка не исправлена. Ошибки показываются сразу — у поля и общим
предупреждением «пока нельзя продолжить». Поля проверяются общим
Illuminate-валидатором, правила собраны в `InstallRules`; предметным
остаётся только пароль (`StrongPassword`). Контракт —
[validation.md](validation.md).

1. Откройте `https://<сайт>/install`. При первом обращении создаётся ключ
   `var/install.key` с правами `0600`.
2. Прочитайте ключ в файловом менеджере FastPanel или по SSH
   (`cat var/install.key`) и вставьте его. Без ключа мастер не показывает
   следующие шаги: иначе первый, кто угадает адрес, создал бы себе
   администратора.
3. **Знакомство.** Короткая презентация: что умеет MyDoMo и что будет
   дальше. Кнопка «Начать настройку» ведёт к проверкам.
4. **Сервер.** Проверки PHP, расширений, прав на `var` и `.env`, свободного
   места, пользователя PHP, веб-корня и агента служб. «Ошибка» блокирует
   кнопку «Продолжить» и объясняет, что исправить; «внимание» — подсказка,
   например отсутствие Redis или агента. «Проверить снова» перечитывает
   окружение.
5. **База и кэш.** Поля с пояснениями: где живёт база, зачем отдельный
   пользователь, чем Redis отличается от файлов. «Проверить подключение»
   прогоняет БД и Redis и показывает результат, не выполняя миграции.
   Если подключение не удалось, шаг остаётся открытым, поля подсвечены,
   кнопка «Продолжить» недоступна. Пароль базы хранится в сессии до конца
   мастера и не возвращается в HTML; пустое поле при возврате на шаг
   означает «оставить сохранённый».
6. **Хозяин дома.** Логин, имя, пароль и часовой пояс. Ошибки логина или
   несовпадение паролей показываются у полей; установка не начинается.
   Кнопка «Установить MyDoMo» пишет `.env`, выполняет миграции, создаёт
   администратора и удаляет ключ. После успеха `/install` отвечает 404.

Поля формы:

| Поле | Значение |
| --- | --- |
| Сервер, порт | Адрес MySQL/MariaDB, обычно `127.0.0.1:3306` |
| Имя базы | Существующая база или новая, если включено создание |
| Создать базу | Нужны права на `CREATE DATABASE`; иначе создайте базу в FastPanel |
| Пользователь, пароль | Учётная запись MySQL именно для MyDoMo |
| Хранилище кэша | `Redis` для рабочей установки, `Файлы` — только одна машина |
| Администратор | Логин 8–64 символа, пароль от 8 символов со спецсимволом |
| Часовой пояс | Часовой пояс PHP, событий и журналов |

Проверка Redis предупреждает, если `maxmemory-policy` вытесняет ключи:
блокировки worker живут в кэше, и при вытеснении два процесса могут взять
одну задачу. Для MyDoMo подходит `noeviction` или отдельная база Redis.

Страница использует маскота, спокойные анимации и уважает
`prefers-reduced-motion`: при системной настройке «меньше движения»
анимации отключаются.

## Команда

```bash
php bin/mydomo install --db-name=mydomo --db-user=mydomo --db-password='...' \
  --db-create --admin-login=sysadmin --admin-name='Администратор' --admin-password='...'
```

Параметры и значения по умолчанию — [console.md](console.md#install).
Команда полезна, когда браузерный доступ закрыт или установка автоматизируется.
Пароль в аргументах остаётся в истории оболочки; на обычном сервере
предпочтительнее страница.

## Что записывается

`.env` получает ключи из [configuration.md](configuration.md):
`APP_TIMEZONE`, `APP_DEBUG` (выключен), `DB_HOST`, `DB_PORT`, `DB_NAME`,
`DB_USER`, `DB_PASSWORD`, `CACHE_DRIVER` и при Redis — `REDIS_HOST`,
`REDIS_PORT`, `REDIS_DB`, `REDIS_PASSWORD`. Посторонние ключи и комментарии
файла сохраняются.

Также автоматически создаётся APP_KEY для шифрования секретов; существующий
ключ сохраняется при повторной попытке. Вводить или копировать его в мастере
не требуется. Это не одноразовый `var/install.key`. Ключ приложения нужно
сохранять вместе с резервной копией окружения; контракт —
[encryption.md](encryption.md).

Затем выполняются миграции ядра, создаётся администратор с объектом Users
и ролью `admin`, пишется `var/installed.lock`. Пароли не попадают в журнал
и в отчёт об установке.

## Повторный запуск и сбои

`.env` пишется до миграций, чтобы после сбоя повторный запуск шёл в ту же
базу. Миграции идемпотентны, администратор создаётся один раз. Признак
установки — `var/installed.lock`; дополнительно мастер считает установкой
действующего администратора в базе, поэтому потеря lock не открывает
установщик заново. Если база уже содержит администратора, форма сообщает
об этом и предлагает другую базу.

## Что остаётся вручную

- systemd-юниты `mydomo-agent`, `mydomo-core@queue`, `mydomo-core@events`,
  `mydomo-core@timeouts`, `mydomo-core@maintenance` — [deploy.md](deploy.md);
- перезагрузка PHP-FPM после изменения `.env` и прав;
- проверка, что nginx отдаёт `public` и не открывает `.env`, `var` и `vendor`;
- резервное копирование базы: установщик его не делает;
- импорт данных из alpha — отдельная операция, а не режим установщика.

## Ограничения

Установщик не переносит данные из alpha, не создаёт демонстрационный дом,
не настраивает nginx/FPM и не запускает службы. Откат установки не
предусмотрен: повторная установка на ту же базу отклоняется, а восстановление
делается из резервной копии. Раскладка `releases/current` появится вместе
с обновлением; сейчас установка предполагает один каталог приложения.
