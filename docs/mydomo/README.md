# MyDoMo

MyDoMo — новая ветка приложения на PHP 8.2+ и компонентах Illuminate 12.
Это не полный Laravel: используются собственные Application, kernel,
сессии, очередь и модульный SDK. Внешний вид панели сохраняет дизайн alpha,
реализация — Blade, Alpine и локальный бандл.

Справочник сверяется с текущим кодом; дорожная карта описывает будущую
работу. Зелёный исторический чекбокс не заменяет проверку сегодняшней сборки.
Актуальные границы сведены в [limitations.md](limitations.md).

## Что уже реализовано

- HTTP-вход `public/index.php`, контейнер, роутер, обработка ошибок,
  request ID, security headers и режим обслуживания.
- Вход администратора, проверка действующих сессий, CSRF, роли,
  API-токены и лимит попыток входа.
- Единый раздел «Классы»: дерево классов и подклассов, карточка класса,
  объекты, свойства и методы внутри неё; значения и история живут у объекта.
  Отдельных пунктов меню для объектов, свойств, методов, значений и истории
  нет. Плюс страницы сценариев, пользователей, локаций, настроек, событий,
  очереди, журналов, webhook, уведомлений и UI Kit.
- Репозитории новой lowercase-схемы: наследование классов без ограничения
  глубины, объектные свойства/методы, история значений, асинхронный конвейер
  `property.changed` по полосам (OnChange, история; доставка модулям — в их
  очереди `module.<id>`) с защитой от повторения свойства в цепочке.
- История: выборка по периоду и агрегаты одним SQL (`HistoryQuery`), обёртки
  `history()`, `getHistoryAvg/Min/Max/Sum/Count`; `$this` в методе — контекст
  объекта с `get/set/history/call/notify`.
- Логи: каналы `app/http/security/queue/events` в отдельные файлы с суточной
  ротацией; у каждой записи `system_errors` свой файл с контекстом и trace,
  открывается из `/errors`. Retention чистит историю, журнал, упавшие
  задания, таймеры и ошибки по `config/retention.php` (`db:prune`,
  `core-worker maintenance`).
- CacheStore, долговечная очередь, именованные обработчики и таймеры
  (включая аренду таймера).
- SDK-модули: манифест, ModuleDb/ModuleBus, lifecycle, миграции, helpers,
  маршруты, фоновые задачи, права из манифеста, ассеты и purge; проверка
  legacy-вызовов `module:check`; пример `modules/example_sdk`.
- Настройки модулей из `module.json` с общим экраном
  `/admin/modules/<id>/settings` и подписки на свойства через
  `$context->subscriptions()`: модуль не подписывается за соседний и не
  рисует собственную форму параметров.
- Worker модуля, отдельные процессы очереди/событий/таймеров и systemd-контроллер
  с административным Unix-socket агентом. Linux и live Redis проверяются
  отдельно от тестов на SQLite/array.

Ядровые страницы живут в `src/Http/Controllers/Core` и
`resources/views/pages`, меню — в `CoreSections`. Они не являются
`modules/core`, не устанавливаются и не отключаются через SDK.
MQTT/Zigbee и внешние интеграции — отдельные модули; их полный перенос
ещё не завершён. Шаблонный каталог `modules/core` остаётся для SDK-модулей
типа core, а не для CRUD-страниц приложения.

## Что не следует считать готовым

Новый установщик, обновление с откатом, API v2/OpenAPI, импорт данных из
alpha, production-Docker, sandbox пользовательского PHP, автоматическая
выдача разрешений SDK и полная совместимость сценариев alpha. `say()` теперь
пишет информационное уведомление вместо старого Shoutbox; это не реализация
речевого вывода. Конкретные ограничения — [здесь](limitations.md).

Старые `docs/agents`, `docs/user`, `docs/deploy` в основном описывают alpha.
Они могут объяснять происхождение дизайна или старый runtime, но не служат
готовой инструкцией развёртывания MyDoMo. Alpha-runtime из этой ветки удалён;
его реализация остаётся в ветке `alpha`.

[Мастер-план](../todo/mydomo.md) хранит этапы и принятые решения.
[Журнал аудита кода](core-audit.md) — датированный снимок проверки,
а не руководство по запуску. При изменении публичного поведения обновляйте
профильный документ и ссылки этого индекса вместе с кодом.

Объём и проверка последней переработки справочника —
