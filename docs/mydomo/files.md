# Файловое хранилище

Для сохраняемых файлов используется Flysystem 3 с локальным адаптером,
подключённый через `FilesServiceProvider`. Структура по умолчанию:

```text
var/files/
  core/                  файлы ядра
  modules/<id>/          отдельная папка модуля
```

Корень задаётся абсолютным `files.root` в `config/files.php`; тесты
переопределяют его временным каталогом. Папки создаются при записи,
при boot ничего не создаётся. Кэш, журналы, сессии, SQLite и служебные файлы
установщика сохраняют свои существующие каталоги. Исходники модуля и
публичные ассеты в файловый диск не переносятся.

## Ядро и SDK

Ядро получает `MajorDoMo\Files\LocalFiles` через DI: это диск `core`.
Модуль получает свой диск через `ModuleContext::files()`:

```php
$files = $context->files();
$files->write('reports/status.json', $json);
$json = $files->read('reports/status.json');

if ($files->fileExists('reports/status.json')) {
    $files->copy('reports/status.json', 'reports/previous.json');
}

foreach ($files->listContents('reports') as $entry) {
    $path = $entry->path();
}
```

В фоновой задаче тот же доступ: `$taskContext->module->files()`.
Собственный id или абсолютный путь модуль в SDK не передаёт. Например,
`weather` пишет в `var/files/modules/weather`, а не в `modules/weather`.
Для файлов модуля не используйте общий диск ядра через DI и прямые
`file_put_contents()`/`fopen()` в произвольный каталог.

Операции LocalFiles:

- `write/read`, `writeStream/readStream` — строки и потоки; получатель
  потока отвечает за `fclose()`;
- `fileExists`, `directoryExists`, `listContents($path, $deep)` —
  наличие и список Flysystem `StorageAttributes`;
- `createDirectory`, `delete`, `deleteDirectory`, `copy`, `move` —
  изменение содержимого; copy/move остаются внутри одного диска;
- `fileSize`, `mimeType`, `lastModified` — метаданные файла.

Пустой путь означает корень своего диска: `listContents('')` перечисляет
его содержимое, `deleteDirectory('')` удаляет только этот диск. Ошибки
Flysystem не маскируются успешным результатом; отсутствующий файл при
чтении вызывает исключение. Проверки формата загружаемого файла, размера,
доступа пользователя и разрешённых расширений остаются у вызывающего кода.

## Границы и удаление

Принимаются только относительные пути. Запрещены абсолютные пути,
`..`, потоки вида `php://`, управляющие символы и символические ссылки
в цепочке пути. Flysystem дополнительно запрещает ссылки при обходе
каталогов. Перед рекурсивным удалением всё дерево проверяется до удаления.
Файлы создаются приватными: 0600, каталоги 0700 на Linux.

Это граница поддерживаемого SDK, не sandbox: модуль остаётся доверенным
PHP-кодом с контейнером и может технически обращаться к PHP-функциям.
Проверка пути не защищает от конкурентной подмены файловой структуры
другим процессом с правом записи. Каталог хранилища не должен быть
доступен на запись посторонним системным пользователям.

При `module:disable` файлы сохраняются. При `module:remove` папка
`var/files/modules/<id>` удаляется вместе с модулем, даже без `--purge`;
чужие папки и диск ядра сохраняются. Флаг `--purge` дополнительно управляет
удалением таблиц и старого SQLite/data-каталога. Файлы встроенных модулей
не удаляются при выключении: сами core-модули удалить нельзя.

Хранилище находится вне `public`, публичный URL автоматически не создаётся.
Выдача и загрузка файлов через HTTP требуют защищённого контроллера.
Резервное копирование должно включать нужные файлы `var/files`, отдельно
от очищаемых runtime-кэшей. Удаление модуля с файлами необратимо без копии.

## Проверки

`LocalFilesTest` проверяет операции, потоки, раздельные диски и опасные пути.
Проверки символических ссылок запускаются на Linux. `ModuleSdkTest`
проверяет доступ через контекст, сохранение после disable и удаление
только своего диска при remove. Все файлы создаются во временных каталогах.
