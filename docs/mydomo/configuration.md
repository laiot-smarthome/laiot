# Конфигурация MyDoMo

Главный источник настроек — `MajorDoMo\Foundation\Config`. Веб и основной
CLI входят через `bootstrap/app.php`: он вызывает `Config::boot($root)` и
передаёт настройки в `Foundation\Application`. Полный Laravel здесь не
используется; наличие ключа Laravel в `.env` само по себе ничего не включает.

## Порядок разрешения значений

1. Переменная процесса с тем же именем.
2. `.env` в корне установки — простые `KEY=VALUE`, комментарии `#`/`;`,
   необязательные кавычки и префикс `export `.
3. Значение по умолчанию в профильном `config/*.php`; параметры подключения
   без базового значения описаны в `SettingsSchema`.

Подстановка `${VAR}`, `.env.local`, константы и alpha-схема не
поддерживаются. Неизвестные ключи просто игнорируются. Тип задаёт вызывающий
код: `Config::string/int/bool`, поэтому `APP_DEBUG=0` — это `false`, а не
«непустая строка».

```php
use MajorDoMo\Foundation\Config;

$debug = Config::bool('APP_DEBUG', false);
$port = Config::int('REDIS_PORT', 6379);
```

## Настройки, подключённые к новому bootstrap

| Ключ | Применение | Значение при отсутствии |
| --- | --- | --- |
| `APP_DEBUG` | Подробности HTTP-ошибок и уровень логирования | `false` |
| `DB_HOST` | Адрес MariaDB/MySQL | `127.0.0.1` |
| `DB_PORT` | Порт БД | `3306` |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | База и учётные данные | Требуют настройки для данной установки |
| `CACHE_DRIVER` | `array`, `file`, `database`, `redis` | `file` |
| `REDIS_HOST` | Адрес Redis | `127.0.0.1` |
| `REDIS_PORT` | Порт Redis | `6379` |
| `REDIS_DB` | Номер базы Redis | `0` |
| `REDIS_PASSWORD` | Пароль Redis | Пустая строка |
| `APP_TIMEZONE` | Часовой пояс PHP и Clock | `Europe/Moscow` |
| `QUEUE_MAX_ATTEMPTS` | Число попыток задания | `3` |
| `QUEUE_RETRY_DELAY` | Задержка повторной попытки, сек | `60` |
| `QUEUE_RESERVATION_TIMEOUT` | Аренда задания, сек | `300` |
| `QUEUE_HANDLER_TIMEOUT` | Лимит пользовательского обработчика, сек | `5` |
| `LOG_LEVEL` | Уровень файловых журналов | `info` |
| `LOG_MAX_FILES` | Число суточных файлов на канал | `14` |
| `RETENTION_HISTORY_DAYS` | История свойств, дней | `90` |
| `RETENTION_EVENTS_DAYS` | Журнал событий, дней | `30` |
| `RETENTION_QUEUE_DAYS` | Ошибки очереди, дней | `14` |
| `RETENTION_TIMEOUTS_DAYS` | Завершённые таймеры, дней | `7` |
| `RETENTION_ERRORS_DAYS` | Системные ошибки и файлы, дней | `90` |
| `RETENTION_BATCH` | Строк в порции очистки | `5000` |
| `RETENTION_INTERVAL` | Интервал фоновой очистки, сек | `21600` |

Пароли задаются в окружении установки, не в примерах и не в репозитории.
Текущий bootstrap создаёт основное соединение с драйвером `mysql`:
`DB_CONNECTION=sqlite` не переключает рабочее приложение. SQLite передаётся
непосредственно в `Application` в изолированных тестах.

## Что настраивается PHP-конфигурацией

`ConfigLoader` загружает `config/app.php`, `cache.php`, `queue.php`,
`logging.php`, `retention.php`, `providers.php`; переданный конструктору
Application массив рекурсивно перекрывает их. Исключение — providers: явно
переданный список заменяет стандартный целиком. Это позволяет однозначно
задавать порядок провайдеров в изолированной сборке. Контракт —
[providers.md](providers.md).

- `views`, `view_cache`, `log` — пути и журнал из конфигурации приложения.
- `queue.table/events_lanes` — таблица и число полос очереди событий из
  `config/queue.php`. Попытки, задержка, аренда и лимит обработчика получают
  значения из перечисленных выше `QUEUE_*`.
- `cache.path` — каталог файлового кэша; `cache.table` нужен драйверу БД.
- `logging.directory/max_files/level/error_directory` — каналы и файлы ошибок
  из `config/logging.php`; `log` перекрывает путь (поток `php://stderr` в
  тестах и CLI), `debug` включает уровень Debug. Каналы пишут отдельные
  файлы с суточной ротацией.
- `retention.history_days/events_days/queue_days/timeouts_days/errors_days` —
  сроки хранения; `retention.batch` — размер порции, `retention.interval` —
  период `core-worker maintenance` в секундах (минимум 300). `0` в сроке
  отключает раздел. Подробности — [logging.md](logging.md).

## Изменение через панель

`/settings` доступен с правом `settings.manage`. Вкладки: «Основные»,
«База данных», «Кэш и Redis», «Очередь», «Журналы», «Хранение данных».
Поля, пояснения, поддерживаемые варианты и привязки к рабочей конфигурации
описаны в `src/Settings/SettingsSchema.php`. Значения по умолчанию берутся
из PHP-конфигурации. `bootstrap/app.php` применяет эту же схему через
`SettingsSchema::environment()`, поэтому сохранённые ключи действительно
используются приложением.

Форма `system-settings` сохраняет раздел через Yoyo POST `/yoyo` с CSRF.
Сервис проверяет поля на сервере: неизвестные ключи, параметры соседнего
раздела, неподдерживаемые варианты, неверные числа и переносы строк
отклоняются. Аренда задания должна превышать лимит обработчика. Поиск
работает по ENV-ключу, названию и описанию, результат ведёт к нужному полю.

Параметры MQTT (брокер, TLS, подписки) — не `.env` и не общий экран
настроек: они принадлежат модулю и меняются на `/module/mqtt/settings`.
Модуль хранит их в `module_mqtt_settings` и читает через свой сервис
настроек; `Foundation\Config` остаётся для параметров приложения. После
сохранения цикл приёма переподключается сам. Подробности — [mqtt.md](mqtt.md).

Запись выполняется во временный файл в каталоге установки и атомарно
заменяет `.env`; нужны права записи на файл и каталог. Посторонние ключи
и комментарии сохраняются. Блокировка и ревизия файла защищают от
сохранения устаревшей формы; при конфликте нужно обновить страницу.
Секреты не выводятся в HTML и состояние Yoyo. Пустой пароль оставляет
прежний, отдельный флажок удаляет его. Значения окружения процесса имеют
приоритет: UI показывает их источник и запрещает редактирование этих полей.

Перед изменением параметров БД проверяется новое подключение, наличие
основных таблиц и текущий администратор с тем же id, логином и отпечатком
пароля. Проверка не переключает рабочее соединение и не переносит данные.
При отказе проверки `.env` остаётся прежним. Долгоживущие процессы после
сохранения перезапускаются администратором, автоматически UI их не запускает.

Таблица `settings` не является источником системной конфигурации и больше
не редактируется этим разделом. Её оставшиеся репозиторий и обработка
ссылок при переименовании не используются bootstrap. Настройки SDK-модулей
по-прежнему принадлежат модулю и задаются его схемой `module.json`.

## Часовой пояс

`Application` принимает ключ `timezone`, устанавливает PHP timezone и
создаёт `Clock`. `bootstrap/app.php` читает `APP_TIMEZONE` и по умолчанию
берёт `Europe/Moscow`. Поведение времени описано в [database.md](database.md).

## Перезапуск

`Config::boot()` выполняется один раз в PHP-процессе и читает `.env` при
старте. Долгоживущие worker-процессы нужно перезапускать после изменения
`.env`; отдельного кэша конфигурации нет. Очистка `cache:clear` относится к
прикладному `CacheStore`, а не к конфигурации или Blade-кэшу. Её область
действия — в [cache.md](cache.md).

## Отдельная конфигурация systemd-агента

`bin/mydomo-agent` не подключает `bootstrap/app.php`. Он читает JSON
`/etc/mydomo/agent.json`; путь можно заменить переменной процесса
`MYDOMO_AGENT_CONFIG`. Это отдельный привилегированный процесс, его
настройки не следует смешивать с конфигурацией веб-приложения.
Поля и границы доступа — в [runtime.md](runtime.md).

Проверки окружения и команды, меняющие состояние, перечислены в
[console.md](console.md); тестовое окружение — в [testing.md](testing.md).
