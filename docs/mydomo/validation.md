# Валидация входных данных

MyDoMo использует `illuminate/validation` 12 и `illuminate/translation` 12.
`ValidationServiceProvider` регистрирует общую фабрику и русский переводчик.
Зависимость для контроллера, прикладного сервиса или метода `mount()` Yoyo —
`Illuminate\Contracts\Validation\Factory`. Полный Laravel не устанавливается.

## Использование

Правила задаются по ключам, включая вложенные массивы. Например, внутри
метода, получившего `$validation` через DI:

```php
use Illuminate\Contracts\Validation\Factory;
use Illuminate\Validation\Rule;

/** @var Factory $validation */
$validator = $validation->make($input, [
    'name' => ['required', 'string', 'max:100'],
    'mode' => ['required', Rule::in(['mqtt', 'local'])],
    'devices' => ['sometimes', 'array'],
    'devices.*.name' => ['required', 'string', 'max:100'],
], [], [
    'name' => 'Название',
    'mode' => 'Режим',
    'devices.*.name' => 'Название устройства',
]);

if ($validator->fails()) {
    $errors = $validator->errors()->toArray();
    // Передайте ошибки полей существующей форме и завершите обработку.
} else {
    $data = $validator->validated();
    // Передайте проверенные данные прикладному сервису.
}
```

`errors()->toArray()` возвращает `поле => список сообщений`;
`errors()->first('name')` — первое сообщение конкретного поля.
Дополнительные сообщения передаются третьим аргументом `make()`, названия
полей — четвёртым. Локальные переводы находятся в
`resources/lang/ru/validation.php`; источник — Laravel Lang Team, MIT,
лицензия сохранена в `resources/lang/LICENSE`. Во время работы приложения
переводы не загружаются из сети.

Для входа с явной обработкой исключений можно вызвать
`$validation->make($input, $rules)->validate()` или `$validator->validate()`:
при ошибке выбрасывается `Illuminate\Validation\ValidationException`,
его `errors()` возвращает ошибки по полям.

## Границы интеграции

- Фабрика доступна по контракту, конкретному `Illuminate\Validation\Factory`
  и имени `validator`; это один экземпляр на Application. Новая проверка
  создаётся через `make()`, состояние отдельных форм не смешивается.
- `unique` и `exists` используют менеджер из
  `DatabaseManager::resolver()`: то же соединение и текущую транзакцию,
  что репозитории приложения. Обычная проверка формата не открывает БД.
- Подключение пакета не включает Laravel FormRequest, фасады,
  `$request->validate()`, автоматический redirect или ответ 422.
  Контроллер и Yoyo явно обрабатывают `fails()` либо перехватывают
  `ValidationException`; необработанное исключение kernel считает ошибкой
  сервера. API возвращает свой ответ 422 с ошибками полей.
- Ошибки полей показываются у полей; общий результат операции админки —
  через Notify по [UI Kit](ui-kit.md). Не передавать секреты обратно в форму
  и не помещать тексты ошибок в GET-параметры.
- Правила, зависящие от Laravel Auth/Gate, например `current_password`
  или `can`, требуют соответствующей интеграции и автоматически не работают.
  Проверки доступа выполняются через существующую авторизацию MyDoMo.

## Правила разработки

Используйте штатные required, nullable, sometimes, string, integer,
boolean, email, min/max, in, regex, unique, exists и правила массивов.
Не создавайте отдельные движки валидации и ручные аналоги готовых правил.
Сначала проверьте возможности `Rule::*` и условных правил Illuminate.

Для большого или повторяемого набора допустим прикладной класс правил,
используемый контроллером и Yoyo. Собственные правила нужны только для
предметных ограничений, которых нет в Illuminate; повторяемое правило
реализует `Illuminate\Contracts\Validation\ValidationRule`.

В сервис передаются только проверенные поля. `validated()` не преобразует
все значения в PHP-типы автоматически и не заменяет явную нормализацию.
Для вложенных объектов задавайте разрешённые дочерние поля либо список
ключей в правиле `array`, чтобы не пропустить лишние входные данные.

Авторизация и CSRF проверяются отдельно. Доменные инварианты и ограничения
БД сохраняются: предварительная `unique` не исключает гонку при записи.
В `Rule::unique()->ignore()` передавайте идентификатор доверенной записи,
полученной сервером, а не произвольное значение из запроса.

Существующие формы переносятся при их доработке с сохранением поведения.
Декларативные схемы настроек SDK остаются источником правил, а общий
валидатор используется за их действующим контрактом.

## Проверка

`tests/Feature/ValidationTest.php` проверяет общую фабрику, вложенные поля,
русские сообщения, условные правила и `unique`/`exists` внутри транзакции
SQLite в памяти. Рабочий bootstrap и внешние сервисы не подключаются.
