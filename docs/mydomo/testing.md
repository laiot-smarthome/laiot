# Проверки MyDoMo

Основной набор должен оставаться быстрым и проверять контракты, а не
каждую кнопку. Для исправления ошибки достаточно адресного регрессионного
сценария; после него — общий набор, если меняется общий контракт.

## Что запускается

```bash
php vendor/phpunit/phpunit/phpunit --testdox
composer check
php tests/config_smoke.php
php tests/docs_quality_smoke.php
```

`phpunit.xml` по умолчанию выбирает MyDoMo (tests/Feature). Отдельный suite
Integration может обращаться к специально заданному тестовому MariaDB;
его нельзя включать, не проверив выделенные MYDOMO_TEST_DB_* и данные
сценария. Обычная рабочая БД не подходит.

`composer check` последовательно выполняет parallel-lint, PHP-CS-Fixer
в dry-run, PHPStan и PHPUnit. При первой ошибке последующие стадии могут
не запускаться: нельзя считать PHPUnit пройденным только по началу лога.
Rector dry-run — отдельная команда composer rector:dry, не часть check.

Файла tests/routing_smoke.php в текущей ветке нет. Он встречается в
исторических инструкциях, но не должен оставаться обязательной командой.
Маршруты нового ядра покрывают Feature-тесты.

## Изоляция

phpunit.xml задаёт APP_ENV=testing, DB_CONNECTION=sqlite,
DB_DATABASE=:memory: и безопасные значения драйверов. tests/phpunit.php
проверяет их и подключает autoload + SessionFixture, а не bootstrap/app.php.

Сами Feature-тесты явно собирают Application: SQLite в памяти, ArraySession,
array-кэш либо выделенное временное хранилище для теста драйвера.
Переменные окружения сами по себе не заставляют произвольный экземпляр
Application использовать SQLite/array. Не добавляйте в тест рабочий
bootstrap «для удобства».

SDK-тесты используют отдельные временные SQLite-файлы для нескольких
экземпляров приложения. SessionFixture согласует сессию с существующим
администратором и stamp; нельзя обходить auth только ради фикстуры.
MaintenanceTest хранит флаг в отдельном временном каталоге.

Новое обращение к HTTP, почте, Redis или иной внешней системе в тестируемом
коде требует fake/mock или отдельного явно изолированного стенда.
Тест конструирования RedisStore без операции чтения не является live-
проверкой Redis. Файлы и состояние теста очищаются после выполнения.

Запись свойства асинхронна: `sg()`/`setValue()` только сохраняют значение и
ставят задание. Тест, который проверяет журнал, историю, OnChange или
подписчика, вызывает `DrainsEvents::drainEvents($app)` — он обходит все
полосы `events.<n>`, затем очереди `module.<id>` и выполняет задания до
пуста. Не отключайте очередь «для удобства»: тогда тест перестаёт проверять
реальный конвейер.

MQTT проверяется без брокера: `MqttModuleTest` поднимает схему на SQLite,
вызывает обработчик входящего сообщения напрямую и подменяет
`PublisherInterface` записывающей реализацией. `worker mqtt --once` в тесте
ограничен двумя секундами и проверяет, что фоновая задача не висит и не
требует запущенного брокера. Сетевое соединение, TLS и keepalive так не
проверяются — для них нужен живой стенд.

## Что подтверждают уровни тестов

| Уровень | Подтверждает | Не подтверждает автоматически |
| --- | --- | --- |
| Чистая логика | Нормализация, значения, конфигурационные функции | Реальные соединения |
| SQLite/Feature | Репозитории, контроллеры, сессии, обработчики | Все особенности MariaDB |
| Application.handle | Kernel, middleware и ответ | nginx, proxy, cookie браузера |
| Браузерный сценарий | Критичный пользовательский поток | Все операции всех страниц |
| Linux-стенд | pcntl/posix, процессы и окружение стенда | Установленные production systemd-юниты |

Для входа и CRUD проверяйте auth/CSRF и реальную запись; для фоновой
работы — повторы, ошибку и завершение. Не создавайте тест, который только
повторяет выражение из реализации или проверяет наличие строки в коде.

## Документация

Для Markdown запускается docs_quality_smoke.php: UTF-8, front matter,
аудитория, категории, относительные .md-ссылки, язык. Это проверка структуры,
не доказательство истинности описанного API.

Дополнительно вручную сверяются маршруты с routes/CoreSections, методы
с сигнатурами классов, параметры команд с configure(), значения Config
со схемой и bootstrap. Примеры с планируемыми функциями явно помечаются.
Для одной правки документации не нужны запуск worker, миграция, очистка
кэша и полный runtime-тест приложения.

## Ассеты и локальный просмотр

```bash
node --check resources/js/app-mydomo.js
npm run build
```

Сборка создаёт локальные mydomo.js/mydomo.css. AdminAssetsTest проверяет
отсутствие jQuery/старого alpha-runtime и ссылки страниц на новый бандл.
Изменения шаблонов требуют подходящей визуальной проверки, а не только
синтаксиса JS.

`php -S 127.0.0.1:8080 -t public tools/dev-server.php` поднимает локальный
kernel без Docker: статика отдаётся из `public/`, остальные пути уходят в
`public/index.php`. Нужны запущенные БД и Redis (если выбран). Команды
health/doctor используют сервисы своей установки, их эффекты —
[console.md](console.md).
